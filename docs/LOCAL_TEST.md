## 建议测试顺序

1. 普通账号登录，进入题库，完成「初识 Flag」。答案在题面中，也有静态附件。
2. 打开知识库的入门教程，标记学习完成；技能树会结合阅读记录和个人解题解锁后续节点。
3. 创建战队，通过邀请码邀请另一个账号加入；队长可以转让或轮换邀请码。
4. 报名「本地功能体验赛」，进入赛场答题、启动战队专属环境，检查排行榜。该赛事开放到 2026-10-29，开赛后的报名会锁定成员。
5. 练习题「端口直连靶机」显示 `localhost:随机端口`，浏览器打开 `http://localhost:端口/flag`。
6. 「泛域名靶机」显示 `http://实例UUID.labs.localhost`，可直接点击打开靶机，再访问 `/flag`。
7. 「专属附件示例」点击生成，下载 ZIP，解码 `challenge.txt` 的 Base64，再提交 Flag。
8. 「我的环境」测试续期、停止；默认个人或战队最多同时存在 2 个环境，动态附件也计入配额。
9. 管理员进入管理中心，测试题目、赛事、公告、文档、技能树、上传附件、用户状态、资源和审计。

「公共容器示例」已由管理员启动。普通用户只能使用，不能重启或停止公共环境。示例镜像是用于检查平台功能的教学环境。

## 本地域名

本次 `.env` 使用 `CHALLENGE_DOMAIN=labs.localhost`、`DOMAIN_SCHEME=http`、`GATEWAY_HTTP_PORT=80`。现代浏览器通常将 `.localhost` 解析到回环地址；实际 curl 访问已通过。若使用不支持此规则的客户端，可用 `curl --resolve 域名:80:127.0.0.1 http://域名/flag` 验证，或自行配置本地 DNS。

端口 8080 为平台，回环端口 80 为题目网关；两者均未绑定公网。正式部署的公网 DNS、TLS、出口防火墙与地址池按 [部署文档](DEPLOYMENT.md) 配置。

## 服务管理

```sh
docker compose ps
docker compose logs --tail=100 api worker gateway
docker compose stop          # 停止平台服务，数据保留
docker compose up -d         # 重新启动
```

**停止平台前，先在管理中心回收题目环境。** 动态创建的题目容器不属于 Compose；停止 Worker 后它们无法自动到期回收。不要用 `docker compose down -v` 作普通停止命令。

```sh
npm ci
npm run typecheck
REQUIRE_DB_TESTS=1 npm test

npm run smoke
```

`smoke` 需要本地管理员与 player 账号文件，以及已构建的 `nebuctf/example-web:local`、`nebuctf/example-attachment:local`。它会创建/复用 4 道资源示例题，进行真实提交和附件上传，检查端口、HTTP/WebSocket 代理、下载与主动回收，保留公共容器。只在开发测试环境运行。不要与手动操作同一测试账号并行运行。

## 新增功能体验

- 练习场默认展示目录，每页 24 题，支持搜索、分类和页码跳转。当前本地数据不足一页；分页已用 27 题数据库夹具验证，无需为展示页数堆放空题。
- 「分步解码」有 Base64、十六进制、ROT13 三个小题。每步独立计分，只有三步全部通过才算整题完成。可测试任意顺序提交、重复提交以及错误反馈。
- 题单已提供「入门练习」「环境与附件」，管理中心可以新建和排序题单。
- 「分组功能体验赛」支持公开组、校园组，队长选择战队和组别报名。报名后点击进入赛场，赛题占独立整页。既有赛事与报名记录未改动。
- 比赛页展示海报与日历，管理员可以上传新海报。选择日期查看跨天赛事。
- 无战队时从报名提示前往战队页；额度用满时从错误提示前往「我的靶机」释放实例。启动、生成、续期和销毁显示持续推进的活动进度，确认完成后自动退场；附件下载只显示按钮状态并支持取消。

新增示例可幂等复用：`node scripts/seed-experience.mjs`，固定访问本机 8080，读取现有管理员文件，不创建账号、不自动报名或提交答案。

- 首页查看公告、近期比赛、日历和解题动态；从主导航进入练习场，目录仍按每页 24 题分页。
- 比赛详情的规则、报名与海报分栏；进入比赛后顶部改为比赛菜单。「返回大厅」回到比赛列表，不撤销报名。赛题直接进入作答工作区。
- 多小题在左侧目录分别标注通过状态；整题全部完成后，提交框替换为「该题目已解答」。可以切换其他页面，检查轻量淡入淡出；点击首页或大厅的比赛卡片时检查展开过渡。开启系统减少动态效果后应跳过展开。
- 靶机卡片提供复制和新标签页访问，并显示剩余时长。启动、续期、销毁及专属附件生成的进度持续推进，完成后消失；附件下载不出现进度条。
- 本轮以 60 秒 TTL、500 millicores CPU、256 MiB 内存的实际 Docker 靶机验证续期和自动回收，确认到期状态为 stopped，容器和独立网络已删除。浏览器关闭也不影响 Worker 回收。

本轮未打开本地浏览器。卡片展开、菜单淡入淡出、提交反馈与进度退场的实际观感，以及窄屏和键盘操作，请在本地页面检查。


## 比赛导航与情境动效复核

1. 未报名用户打开比赛：左上返回大厅，右上账户；依次显示概览、公告和排行榜，不显示赛题/靶机。
2. 报名后，赛题入口仅在比赛进行中出现；手动输入受限赛题或靶机地址应回到概览。公开排行榜和公告仍可访问。
3. 首页及比赛大厅卡片采用同样的展开行为；普通菜单淡入淡出，题目切换只更新题面，不平移整个屏幕。
4. 点击比赛卡片后应立即开始展开，不等数据到达。展开并停留半秒后若仍未加载完成，在内容区中央显示加载动画；此时前往其他页面，迟到的请求不能把页面拉回比赛。
5. 老浏览器不支持 View Transitions 时使用普通过渡；启用减少动态效果时不执行卡片展开。详情中的报名、时间和规则仍正常可操作。


## 本轮交互检查

- 顶部主题按钮切换亮色、暗色、跟随系统；刷新后应保留。学习与账户下拉都用点击打开。
- 我的战队先显示列表；无战队时有引导，创建/加入进入独立页面，中间有 OR 分隔。
- 我的靶机不出现公共环境；在对应题目里仍可以使用公共环境。地址右侧为复制和打开图标。
- 启动时只有活动进度，就绪后才出现剩余时间进度。启动、生成或销毁之后 60 秒内，再次修改同一道题的环境应被阻止；战队成员共用冷却，刷新不能绕过。
- 失败环境保留原因；冷却结束后可从题面重试。错误 Flag 保留输入并抖动，小题目录可独立展开和收起。
- 首页整条公告可点击，公告页每条有独立背景和间距。比赛、技能树、题单和文档卡片先展开，再显示详情。


## 比赛列表与动态

- 刷新比赛大厅，卡片海报高度固定，状态位于右上角；宽屏按可用宽度增加列数。首页近期比赛使用相同卡片。
- 点击卡片，海报和文字随放大渐隐，变成纯色表面后再显示比赛详情。
- 比赛公告仅出现该比赛的公告，不混入首页公告。
- 已报名用户或管理员进入开赛后的比赛，右下角有可收起的「比赛动态」。通过小题、首三次解出或发布预先关联的草稿题后，约 5 秒内可看到更新；收起时出现新动态数量。新动态来自真实操作，不填充演示记录。
- 封榜后的通过暂不出现在动态中，比赛结束后再显示；错误和重复 Flag 不新增动态。旧赛题没有可靠上线记录时，不伪造历史上线通知。


## 管理页面与技能树绘制

1. 打开 `/admin/challenges`，查看分类、类型、分值、归属、发布状态与定时上线时间；用搜索、筛选、页码切换列表。
2. 点击新建或整行题目，确认进入独立页面；保存后应回到原筛选页。比赛、题单、文档、技能树、公告同样适用，编辑 URL 可直接刷新。
3. 新建技能树，添加节点，在右侧选择文档/练习，拖动节点位置，从底部连接点连到后续节点顶部。检查循环连线被拒绝、删除节点会移除相关连线；试用「添加子节点」和「树形排列」，根节点应在上、分支向下展开。保存并重新打开，位置和依赖应保留。
4. 发布关联内容和技能树，再进入学习页，检查公开画布与管理端位置一致、完成与锁定状态正确；可平移、缩放和显示全部节点。
5. 新建草稿题设置未来上线时间，到期前不应出现在公开题库，到期后 API 自动启用；预先关联的比赛题也会有上线动态。测试时使用独立测试题，避免影响现有比赛。
6. 比赛、题单和技能树选择题目支持远程分页，翻页不能清空已选项。题单选题最多 500 题、比赛 200 题。
7. 比赛详情的报名数应显示完整数字，零报名显示 0，按战队而非成员计数。

本轮未打开本地浏览器，画布的拖动手感、缩放、窄屏布局请在页面中复核。自动化验证记录见 [验证记录](VERIFICATION.md)。


## 卡片、动态面板与技能树往返

1. 点击比赛或技能树卡片：加载时整卡不应变暗；内容随卡片展开逐渐消失，背景连续扩大，铺满后停留半秒再显示详情。分别检查明暗主题与系统减少动态效果。
2. 在进行中的比赛里连续展开、收起右下角动态：宽高应连续过渡，快速反向点击不闪空白；重新展开应保留列表滚动位置。
3. 靶机或专属附件失败后，重试操作应位于卡片头部；长诊断默认收起，展开详情仍能看到重试。冷却期间按钮显示剩余秒数，资源达到上限时保留管理入口。
4. 打开历史已完成题目：「该题目已解答」静态显示；当次首次正确提交仍有成功动效，错误提交继续抖动输入框。
5. 打开技能树，使用加减按钮逐支展开、点击节点查看内容、进入分支和返回上一级；已有手动坐标可在「作者布局」查看。窄屏点击节点后滚动至详情。
6. 从技能节点打开教程或练习，点击「返回技能树」应恢复选中的节点与原分支；直接刷新教程/题目页面后返回仍有效。

本轮不打开本地浏览器。自动检查覆盖数据与 DOM 交互，原生视图过渡、宽高动画和窄屏观感请在测试页面复核。


## 排行榜

1. 在比赛中打开排行榜：上方为前五名积分走势，下方按分类排列题目矩阵。尝试收起图表和拖动时间范围。榜单每 15 秒更新，结束后可手动刷新。
2. 切换组别、搜索战队、翻页，检查搜索结果保留原名次，组内榜同时显示总榜名次；刷新页面应保留筛选。「我的排名」直接定位当前报名战队。
3. 查看多 Flag 题目：各小题分别显示状态，未全部通过时整题解出数不会提前增加；一、二、三血以不同颜色奖牌显示，普通解出为勾选。点击队名或已解格查看通过时间。
4. 超过 36 个计分单元时用分类或左右按钮切换列组。宽屏滚动时队名与总分固定，窄屏仅固定队名，横向滚动局限于表格。检查明暗主题和长队名。
5. 对独立测试赛事设置封榜，检查封榜后提交不出现在分数、矩阵、解出数和曲线中，赛事结束后恢复。未开赛时不得显示赛题名称。勿调整正在使用的赛事时间来测试。
6. 练习排行榜保持分页选手列表，点击名称查看已解记录；不渲染全部练习题矩阵。


## 题单作答范围

从题单第二页打开任意题目，左侧应只显示该题单的题目，并保持题单排列顺序；切题、搜索、分类筛选和翻页不能混入其他练习。刷新后仍停留在原题单，点击「返回题单」恢复对应页。检查多小题完成状态和手机目录。直接从练习场或技能树打开题目时，仍使用原有练习目录和返回入口。


## 排名范围与战队详情

1. 在配置组别的比赛中选择「全局排名」或某组「组内排名」，搜索、翻页和刷新后检查范围保留；没有组别时不应出现此选择器。
2. 点击队名或已解题目格，查看全局/组内名次、方向雷达和各方向数值。雷达可切换全队或任意队员，零分成员应保持零分图形。
3. 由两名队员分别解答同一道题的不同小题，记录应分别显示真实解答人；队员得分之和等于战队总分，完成整题不再额外计分。重复提交不得转移解答人。
4. 检查队员贡献中的总分、Flag 数、最高分方向，以及零分队员。历史贡献者赛后离队，记录仍保留本人归属并标注已离队。
5. 封榜后的提交不得出现在雷达、队员贡献或解答人记录中；比赛结束后恢复。练习排行榜详情同样有个人方向雷达和解题记录。

## Docker 镜像管理

管理员进入「管理中心 → Docker 镜像」查看 Worker 本地镜像和关联题目。题目编辑页中，未就绪镜像显示拉取入口；已就绪镜像显示测试入口。拉取弹窗可关闭后重开，显示分层进度与诊断日志。可使用允许仓库下的镜像测试下载失败和重试；本地构建镜像会直接显示已就绪。

未发布题目也能测试。靶机支持地址复制和跳转，动态附件支持测试生成和下载；10 分钟后回收，不参与练习或比赛，启停继续遵守 60 秒冷却。测试占用现有资源配额，资源管理列表会标注「测试」。完整配置步骤见 [出题教程](AUTHORING.md#拉取镜像与发布前测试)。


## 本轮新增功能

- 管理员编辑题目和比赛，切换配置标签并保存，确认跨标签输入保留；在赛题计分覆盖分值后核对题库默认值未改变。
- 创建客观题与 CTF/AWDP 混合比赛，设置独立客观/实操时间。用同队两个账号验证自由开始共享时钟，客观题最终提交后全队不可修改。
- AWDP/AWD 的可运行镜像和补丁包按 [攻防示例](../examples/attack-defense/README.md) 创建；详细规则见 [比赛规则](COMPETITION-RULES.md)。示例镜像已在此次本地验收时构建，未向正式题库添加测试题或写入新成绩。
- 使用已报名账号打开进行中的比赛，把右下角动态收起。在另一管理员会话中上线/下线已选题目或新增提示；确认动态实时变化，新提示有独立提醒，展开后消除。第三个窗口提交有效 Flag 可验证解出及三血提示。刷新、断网恢复后核对最近动态，不需要手动刷新页面。

保持 localhost:8080 访问；WebSocket 使用同源 Cookie，不额外传 Token。管理员可以预览动态，未报名普通用户不会建立受保护连接。


## 分组权限配置体验

在管理中心新建一场尚未开始的比赛，选用题目后进入「报名分组」。添加正式组与体验组，为体验组关闭积分、全局排名、三血和动态分值；展开单题权限，取消某题的「沿用组别」并关闭查看。使用不同战队分别报名，开赛后比较赛题目录、只读作答、资源按钮、全局/组内榜以及实时动态。

权限规则见 [比赛组别权限](COMPETITION-RULES.md#组别权限)。开赛后仍可调整查看、作答、资源和报名权限；计分相关权限已锁定。当前已有赛事保留原来的权限与成绩，没有为了演示修改其报名或计分。

资源 smoke 会按服务端返回的 retry_after 等待 60 秒操作冷却，再释放环境，整轮约需两分钟；不跳过或放宽权限与冷却策略。

## 报名与比赛监控

1. 管理员编辑比赛，在报名设置中开启「所有报名均需审核」，或单独打开某组的「报名需要审核」。

## 比赛海报与 WriteUp

1. 打开比赛编辑「基本信息」，上传、更换和移除海报，检查比赛大厅和概览同步更新；在标题输入未保存内容后更换海报，标题草稿应保留。新建比赛需先保存再上传。
2. 打开「WriteUp 提交」，启用并设置截止时间、允许格式和大小上限；保存后重新进入确认配置。未填截止时间时，保存应定位到 WriteUp 标签。
3. 使用已通过报名的战队成员，在提交窗口内打开比赛菜单 WriteUp，上传 PDF 或包含 Markdown/图片的 ZIP。检查实际上传进度、完成后进度移除、提交人/版本及下载。未开始或已截止时不显示上传控件。
4. 两位队友先选择文件，再依次提交：后提交者应看到版本冲突；刷新并重新选文件后可替换。新加入的队员不能访问旧比赛报告。
5. 管理员在「管理 → WriteUp 管理」检查未提交列表、组别筛选、每页 10 条、单份下载与批量导出。在左侧预览并填写意见、退回；队员补交后应显示新版本、清除旧反馈，历史保留。截止后需要补交时先修改截止时间。
6. 上传错误格式、超限文件，检查错误就地显示且可重试；测试暂停参赛、无权限直接访问、文件替换与旧链接处理。必交标记只用于收集核对，不应改变成绩。

## 立即展开与加载等待

1. 在浏览器开发者工具中禁用缓存并启用慢速网络，分别点击比赛、技能树、题单和教程卡片。点击后应立即放大，原文字和海报随放大渐隐；放大完成后保留纯色背景半秒。请求未完成时，加载动画应出现在展开后的内容区中央，数据到达后移除并显示内容。正常网络下也应满足展开与停留时长。
2. 桌面练习列表点击整条题目：列表向左收拢为目录，右侧题面随后显示。慢请求时右侧应居中显示加载动画。点击返回题库时，侧栏反向展开为列表，并保留当前分类、搜索与页码；切换已打开题目不重播收拢动画。窄屏使用原有目录抽屉，直接进入题目。
3. 从比赛概览、题目和排行榜分别点击「返回大厅」：使用普通页面切换，不缩小内容或额外停留空白，页头账户入口保持可用。
4. 加载期间返回目录或打开其他页面，随后恢复网络：不应重新进入已离开的详情，也不应残留空白遮挡。模拟详情请求失败，应显示整页错误和重试入口；重试成功后恢复内容。
5. 分别检查亮暗主题、键盘 Enter、Ctrl/Cmd 点击新标签页、减少动态效果和不支持 View Transitions 的浏览器。辅助设置或 API 不可用时直接导航，不额外等待动画时长。

本轮自动检查覆盖真实 React 组件与模拟原生过渡 API 的时序；未打开本地浏览器，实际动画观感由以上步骤复核。


## WriteUp 同屏审核

- 管理员打开 WriteUp 管理：桌面左侧预览、右侧列表，每页 10 支战队。切换战队后搜索、筛选、页码及列表位置保持；批量勾选仅影响导出，不切换预览。
- 用多页中文 PDF 检查翻页、输入页码、缩放、适应宽度及文字复制。切换队伍后应回到文件第一页；明暗主题下文档纸张保持原色。
- 输入审核意见后切换另一队再返回，草稿应保留；确认收到或退回后查看记录。队员更新文件后旧版本不能被误审核，预览提示刷新，刷新后显示新版本。
- ZIP 显示下载入口，未提交队伍显示明确空状态；文件失败时保留右侧列表和下载按钮，重新加载可恢复。
- 限速网络下快速切换队伍，旧 PDF 请求取消，迟到结果不能覆盖当前选择。窄屏上下排布，预览与列表均可滚动。
- 旧 WriteUp 详情链接应进入同屏管理并选中原队伍，保留地址中的筛选条件。

加载过渡另检查：内容刚好在展开结束附近到达时，不应闪出加载图标；已出现的图标应平滑淡出，内容同时显现。
