# 题型、比赛计分与实时动态

题库保存题目及默认分值，比赛保存选题、上线安排、计分覆盖与时间规则。同一场可以混合客观题、CTF、AWDP 和 AWD，不设置限制选题的全局赛制开关。

## 配置顺序

1. 管理中心 → 题目 → 新建或编辑。按内容、计分、靶机、附件和发布标签填写；攻防题额外显示校验配置。
2. 管理中心 → 比赛 → 赛题设置，添加题目，按需排序和启停。选题覆盖完整题库，可按分类、题型筛选，练习场已开放的题目直接标注；练习成绩与比赛成绩分别计算。
3. 展开赛题，在同一处设置上线安排与计分。沿用题库、固定分、动态分和轮次分直接列为选项；每个小题的分值和曲线一起展示。每页 10 题，翻页和折叠保留编辑，保存时校验全部页并定位错误题目。保存后留在编辑页。
4. 在「时间规则」设置比赛时间及客观题、实操题各自的规则，再设置报名组别。
5. 开赛前用普通报名战队验证作答、附件、靶机及计分。开赛后锁定选题集合、时间与计分规则，仍可在已有赛题中调整启用状态、发布提示和安排上线。

## 题型与资源

| 题型 | 作答 | 计分 |
| --- | --- | --- |
| 客观题 | 单选、多选、填空 | 固定分，完全正确得分 |
| CTF | 静态或战队专属 Flag，支持多小题 | 固定、动态、轮次 |
| AWDP | 攻击 Flag 与防守补丁分开提交 | 攻击、防守各为一个独立计分单元，可动态或按轮结算 |
| AWD | 平台为各队部署服务，提交其他队当轮有效 Flag，并上传修复补丁 | 逐轮累计攻击、防守、可用性分 |

静态附件、专属附件生成器和靶机分别配置，可同时提供。私有靶机与生成器各有独立实例和 60 秒操作冷却；停止/删除与启动/生成共用相应冷却。CPU、内存、实例数仍使用全局资源池，补丁构建与校验也占用预留配额。公共靶机不显示在「我的环境」。

客观题的正确选项和允许答案仅管理员可见。多选按完整选项集合匹配，填空要求每个空位匹配，支持忽略大小写和首尾空白。比赛草稿不计分，最终提交须确认，全队只能提交一次，错误答案也锁定；练习可重新作答。到时不会自动提交尚未提交的草稿。

比赛客观题集中在同一张答卷中，左侧按题号跳转。灰色为未作答，蓝色为已填写，绿色为正确，红色为错误，不显示三血与解出数量。填写后可保存全队共享草稿，交卷前确认未完成题数，整卷一次提交。服务端在同一事务中校验权限、时间、题目集合与草稿版本；队友已修改草稿时返回冲突，避免覆盖。重复交卷不重复计分。正式提交的题目锁定，赛后练习单独保存、允许再次修改，不改变正式成绩。切换当前赛题保留尚未保存的输入；离开比赛前请保存草稿。

## 组别权限

在比赛编辑页的「报名分组」直接设置各组默认权限；展开该组的「单题权限」，取消题目的「沿用组别」后单独配置。题目按每页 10 条展示，可搜索。保存比赛后生效。

| 权限 | 行为 |
| --- | --- |
| 允许报名 | 控制新报名，不撤销已报名战队 |
| 参与全局排名 | 关闭后只出现在组内榜，「我的排名」自动进入本组 |
| 查看赛题 | 关闭后隐藏题目、榜单中的该题明细，以及相关比赛动态 |
| 提交答案 | 控制 Flag、客观题草稿/交卷、攻击提交和防守补丁；可保留只读题面 |
| 使用靶机与附件 | 控制启动、续期、下载、生成、AWD 环境与补丁校验 |
| 获得积分 | 关闭后仍记录正确答案和解题进度，所得分数为 0 |
| 参与三血 | 关闭后解题不占用前三次有效解出的名次 |
| 影响动态分值 | 关闭后解题不计入动态衰减的有效队数 |

前两项属于整个组别，后六项可以对单题覆盖，覆盖适用于该题全部小题。配置相互独立：例如体验组可以提交，但关闭积分、全局排名、三血和动态衰减。查看权限是其他题目操作的前提；补丁同时需要作答与资源权限。

旧组别和未分组赛事默认全部允许，练习场不受影响。已报名的管理员遵守本组权限；未报名管理员保留预览入口。首次报名后不能增删组别；开赛后锁定计分、全局排名、三血和动态分值权限，仍可调整报名、查看、作答与资源权限。

权限在服务器执行。收回查看或资源权限后，该组私有靶机和专属附件进入回收流程，AWD 不再为该组创建服务；已排队补丁在开始处理及最终计分前重新检查权限。只关闭作答不会主动停止仍有资源权限的环境。已经取得的公共靶机地址是共享入口，无法按组撤回直接访问；需要严格分组隔离时使用私有靶机。

组别过滤不改变其他战队已获总分。排行榜隐藏无权查看的题名和解题明细，明细受限时注明统计范围。未报名访客仅看到所有组均可查看的题目元数据。WebSocket 按组生成活动快照，重连和权限更新也重新检查可见范围。

该结构参考 [GZCTF Division](https://github.com/GZTimeWalker/GZCTF/blob/develop/src/GZCTF/Models/Data/Division.cs) 的默认权限与逐题覆盖设计。报名审核见下文；当前未引入分组邀请码。

## 分数

比赛覆盖值只保存在比赛与题目的关联上，不改写题库和其他赛事。客观题只允许固定分。多小题的总分是各小题之和，需要在小题处覆盖；题目级分值用于没有小题的题目。

动态曲线与服务端使用同一二次函数：

```text
score(n) = max(minimum, ceil(initial + (minimum - initial) × (n / decay)²))
```

`n` 为该计分单元具有「影响动态分值」权限的有效解出队数，普通动态计分会同步更新此前解出队伍的分数。封榜以封榜截止时间重建可见榜单。管理员报名后按所在组权限参与计分。轮次结算同样遵守计分与动态衰减权限。

轮次属于比赛，在「时间规则 → 比赛轮次」统一设置长度（60–3600 秒，默认 300 秒）。所有轮次计分题从实操阶段开始按同一时钟编号；中途上线的题目加入当前轮次，不从第 1 轮重计。最后一轮截止到实操结束，可短于设定时长。每轮独立保存配置和积分，不重复结算，不再叠加普通解题分。动态轮次分只根据该轮有效得分队数计算，已结算历史轮次不随以后解出数改变。

- CTF/AWDP「沿用已完成状态」开启：已完成的计分单元从完成后的轮次起持续得分。
- 关闭该选项：每轮必须重新提交 Flag 或通过补丁校验，每个单元每轮最多得分一次。普通 CTF/AWDP 的 Flag 本身不会随轮次轮换。
- AWDP 补丁同时通过功能检查与安全检查才完成防守；提交攻击 Flag 不会获得防守分。这里的轮次规则是对完成状态的周期结算，不是自动运行攻击脚本。
- AWD 攻击分为有效攻破的不同目标数量乘该轮攻击单价；同一队、同一目标 Flag 只能计一次。自己的、过期的或其他比赛的 Flag 无效。
- AWD 巡检正常且本轮没有被攻破时获得防守分；巡检正常时获得可用性分。宕机或巡检错误不获得这两项分，错误状态会单独显示，攻击分仍按有效记录计算。当前没有失分转账或负分规则。

AWD 的 Flag 可配置有效 1–5 轮，服务每轮写入新 Flag，历史 Flag 在有效期内仍可提交。该轮等待有效期结束和检查任务完成后结算。榜单详情记录轮次、解答人、方向和队员攻击贡献；系统产生的防守与可用性积分单独列为战队分，不虚构解答人。

## 作答时间

客观题和实操题各自支持沿用比赛时间、固定时段、有效窗口内自由开始。自由开始由任意已报名队员确认，全队共享同一次开始记录。重复点击和并发请求不会重置计时。截止时间取「开始 + 时长」和有效期结束的较早值。

轮次计分包含同时对抗和统一结算，因此实操阶段必须使用统一时间；客观题仍可自由开始。未开始前不开放相应题面与资源；截止后禁止答题、生成、下载和启动/续期环境。资源绝对期限不超过作答截止。比赛动态公开已上线题名和提示更新信息，不返回提示正文、答案或未上线题面。

## AWDP / AWD 补丁与检查器

管理员提供基础靶机镜像、补丁覆盖目录和可信检查器镜像。选手提交标准 tar 或 tar.gz，最多 20 MiB、256 个普通文件；展开后仍限制 20 MiB。禁止绝对路径、路径穿越、链接、特殊文件、扩展头、重复路径。平台不在宿主机解压归档，不执行选手提供的 Dockerfile。

补丁只覆盖 `/app`、`/srv`、`/opt` 及其子目录。平台固定使用已验证基础镜像 ID，生成只有 FROM/COPY 的构建上下文，禁止 ONBUILD。基础镜像须已包含依赖；补丁构建不联网安装软件。容器以非 root 运行，限制 CPU、内存、PID，丢弃 capabilities，检查网络不开放外部入口。

检查器接收以下环境变量：

| 变量 | 含义 |
| --- | --- |
| `TARGET_HOST` / `TARGET_PORT` | 待检查服务的内部地址 |
| `EXPECTED_FLAG` | 该次校验的预期 Flag，仅检查器持有 |
| `CHECK_MODE` | `functional`、`defense` 或 `availability` |
| `CHECK_TIMEOUT` | 检查器自身应遵守的秒数；平台另有外层超时 |

补丁校验依次运行 functional 和 defense，均返回 0 才通过；其他退出码视为校验失败。AWD availability 返回 0 表示正常，1 表示服务失败，其他退出码表示检查器错误。检查器应验证真实功能和预期 Flag，不能仅检查端口连通，也不能把校验脚本、凭据或答案复制到选手环境中。

补丁任务最多排队/运行 5 分钟，每项校验上限 120 秒，且必须在实操作答截止前完成。任务状态为排队、构建、校验、通过或失败，失败后可重新上传。同一个人或战队只允许一个进行中的补丁任务。Worker 重启将中断任务标为失败并回收资源，排队任务继续处理。

AWDP 通过后记录防守分，不替换原攻击环境。AWD 通过后替换本队服务，其他队环境不变，重启继续使用最后通过的修复镜像，服务 Flag 写在 `/run/nebuctf/flag`。需要在代码中读取该路径；服务运行账号必须能读写这个文件。AWD 不开放选手任意 SSH 或宿主 Docker 权限。

可直接运行的基础服务、检查器和修复包见 [攻防示例](../examples/attack-defense/README.md)。Docker 共享宿主内核，生产攻防资源应在独立可信 Worker 主机运行；本次实现不包含虚拟机靶机或多机自动扩容。

## WebSocket 比赛动态

客户端连接 `/api/contests/:id/activity/ws`，使用同源会话 Cookie。服务器验证 Origin、登录和报名权限，推送题目上线、下线、新提示、有效解出和三血标记。收起动态框时，新提示单独显示提醒及数量，打开后标为已读，支持减少动态效果。

数据变更提交后通过 PostgreSQL LISTEN/NOTIFY 通知 API，同场比赛的同组连接共享快照查询。连接成功及重连会补发最近 40 条动态和当前赛题的最新提示更新时间。新提示游标单独保存，不会因大量解题消息挤出 40 条列表而漏掉提醒；这是近期动态流，不是全量历史消息归档。

心跳为 20 秒，客户端断线后以 1–30 秒退避重连。另有每比赛 5 秒校时检查，用于定时上线、权限撤销和通知中断恢复，不是每客户端轮询。单用户最多 4 个连接，缓慢客户端会被关闭。封榜期间不推送封榜后的解题和三血；上线、下线与提示更新照常推送。

Nginx 已转发 Upgrade/Connection，超时为 75 秒；外层负载均衡也要支持 WebSocket。生产 HTTPS 使用 wss，APP_ORIGIN 必须与用户访问地址一致。Vite 开发代理也开启了 ws 转发。

## 报名审核、暂停参赛与作弊线索

比赛「报名与组别」可开启全员审核，也可仅在指定组别开启审核。审核开启前已通过的队伍保持通过状态。管理员从比赛菜单「管理 → 报名战队」查看名单、筛选状态和组别、批量通过待审队伍，点「查看」进入独立页面查看成员、调整组别或填写审核意见。开赛后锁定组别。重复成员、人数超限、禁用成员不能通过审核，批量操作全部成功后才提交。

已通过队伍需要中止参赛时使用「已暂停」。比赛成绩暂时不进入排行，资源停止，赛题提交、附件和 WebSocket 权限同步撤销；重新通过保留既有解题记录。未通过和暂停的原因会显示给对应队伍。审核不替选手启动自由计时。

「管理 → 比赛动态」显示本比赛的提交、题目上下线、提示、报名审核和判题情况，支持搜索与每页 10 条分页，并通过管理员专用 WebSocket 实时刷新。普通选手的右下角动态仍遵守可见性和封榜规则，管理员监控可查看完整提交记录。

「管理 → 作弊线索」记录提交他队专属动态 Flag 的异常。管理员可在独立核实页查看关联队伍、选手和提交，标记待核实、已确认或已排除并填写说明；所有核实记录保留历史。检测命中不等同于已确认作弊，不自动暂停队伍。AWD 中提交对手 Flag 属于正常攻击，不进入该检测。系统仅保存已分发 Flag 的指纹，不保存提交明文。

设计参考：[GZCTF 报名状态控制](https://github.com/GZTimeWalker/GZCTF/blob/develop/src/GZCTF/ClientApp/src/components/admin/ParticipationStatusControl.tsx)、[GZCTF CheatInfo 数据关系](https://github.com/GZTimeWalker/GZCTF/blob/develop/src/GZCTF/Models/Data/CheatInfo.cs)。本平台保留自身的权限、计分和人工核实流程。

## WriteUp 收集

每场比赛可独立启用 WriteUp。提交时间默认从比赛结束开始，也可设置不早于开赛的时间；截止时间不早于完赛。必交标记用于提示和核对未提交名单，不自动扣分、取消排名或改变解题记录。

每支审核通过的战队共用一份当前报告，提交人由比赛设置决定：「仅队长提交」限制当前队长上传或替换，「队长和队员均可提交」允许报名通过时的成员操作，记录实际提交人。未配置此项的旧比赛沿用成员可提交。队员在队长专属模式下仍可查看和下载本队报告及处理意见。赛后离队不会丢失原比赛报告权限；赛后加入战队不会获得旧比赛文件。暂停参赛会阻止查看和提交。旧比赛的历史队员信息无法回溯，升级时以当时成员名单建立快照。

默认允许截止前替换。管理员可确认收到或退回补充；退回后即使未启用普通替换也可重新提交，但仍须在截止前。重新提交会清除旧版处理结果。多人同时提交时只有一个匹配版本的提交成功，其他人需刷新后重新选文件，避免静默覆盖队友的报告。历史记录保留提交/处理人和版本，文件仅保留最新版。

设计参考 GZCTF 的 [选手提交组件](https://github.com/GZTimeWalker/GZCTF/blob/develop/src/GZCTF/ClientApp/src/components/WriteupSubmitModal.tsx) 中的时间限制、文件替换和上传反馈，以及 [管理员收集页](https://github.com/GZTimeWalker/GZCTF/blob/develop/src/GZCTF/ClientApp/src/pages/admin/games/[id]/Writeups.tsx) 的分组与批量导出。ret2shell 的 [按队伍组织 WriteUp 示例](https://github.com/ret2shell/ret2shell/blob/main/crates/bucket/arch/example_game/writeups/team_1/README.md) 用作 Markdown 与配套资源归档参考，不视为其已有同样的在线提交设置。本平台允许 ZIP 打包 Markdown 和图片，后台不解压执行。


## 比赛统一轮次升级（迁移 21）

`contest_ticks` 保存比赛级的轮次编号和起止时间，`contest_rounds` 保留各题的结算明细并关联同一个 tick。赛题只配置分值、持续得分、动态衰减、Flag 有效轮数和攻防/SLA 分值，不能单独设置每轮时长。开赛后比赛时长、实操时间与轮次长度均锁定。

旧数据的历史轮次和得分不重排、不重复结算。已有独立轮次的进行中比赛，先完成已发轮次及 Flag 有效期，再在下一个比赛轮次边界切换；过渡期界面提示轮次切换，旧历史标为历史轮次。已结束比赛保留成绩。旧赛题时长一致时迁移为该比赛时长，不一致时使用 300 秒；请在未开赛的比赛中检查「时间规则」。旧请求中的赛题 `round.interval` 不再作为配置使用。

这一结构参考 [saarCTF 统一 tick 规则](https://ctf.saarland/rules)、[saarCTF 中央计时调度](https://github.com/MarkusBauer/saarctf-gameserver)、[GZCTF A&D 分支的比赛级轮次](https://dimasc.tf/GZCTF/guide/features/attack-defense)。同时查看用户提供的 i春秋后台：轮次时长位于比赛基础设置，赛题分别配置积分。该后台只作功能流程参考。
