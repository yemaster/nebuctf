# 比赛与题目导入导出

管理员在「管理中心 → 比赛 / 题目」列表中点击导出图标，或从编辑页点击「导出」。列表顶部的「导入」进入独立页面。

1. 选择 NebuCTF ZIP 文件包，等待校验。
2. 查看题目、类型、小题数及附件数。超过 10 题时分页显示。
3. 确认名称。导入比赛时选择未来开赛时间；比赛结束、封榜、报名窗口、作答阶段、赛题上线和 WriteUp 时间按相同偏移量平移。
4. 点击「确认导入」，成功后进入新条目的编辑页。

导入创建新 ID，不覆盖已有数据。单独导入的题目默认未启用；比赛默认未发布，包内赛题保留启用状态，关闭练习场可见性。确认配置后再发布。

## 包含的内容

| 类型 | 内容 |
| --- | --- |
| 题目 | 题面、分类、难度、题型、静态 Flag 校验值、动态 Flag 模板、小题及环境变量、基础计分、提示、客观题答案、靶机与动态附件配置、AWDP/AWD 检测配置、静态附件 |
| 比赛 | 上述所有赛题，以及海报、比赛公告、作答阶段、统一轮次时长、单题计分覆盖、定时上线、分组权限、提示扣分、提交限制、资源配额、观战、练习模式和 WriteUp 设置 |

Docker 镜像只导出引用和配置，镜像文件需在目标平台拉取。运行中的靶机、动态生成附件、选手账户、报名、提交记录、成绩及选手 WriteUp 不在文件包内。这是内容迁移功能，不替代数据库和文件卷备份。

比赛、题目、小题、提示、静态附件和分组使用新 ID；分组单题权限、计分覆盖、提示扣分及附件链接自动重映射。题面中的外部网址保持原样。

## 跨站导入

静态 Flag 目前采用站点密钥进行 HMAC 校验，平台没有保存其明文。同一密钥下可以保留校验值；来源密钥不同时，导入页列出需要重新填写的 Flag。动态 Flag、模板与客观题答案可直接迁移。站点密钥不会进入导出包。

指定参赛战队始终需要重新选择，访问范围仍保留原限制。邀请码在相同密钥下保留，跨站时需要重新设置。未完成这些配置的比赛无法保存为可报名的公开条目。导出包含题目答案及检测配置，应作为管理员资料保存。

## 格式与限制

文件格式为 `nebuctf-content`，版本 `1`。ZIP 中包含 `manifest.json` 和 `files/<UUID>` 资源文件。配置使用现有题目及比赛校验规则；每个资源记录名称、大小和 SHA-256 校验值。不兼容 CTFd 或 GZCTF 的原生文件包。

- 上传文件最大 256 MiB，展开后的配置与资源合计最大 254 MiB。
- 配置最大 8 MiB，单个静态附件最大 20 MiB，海报最大 5 MiB。
- 每包最多 200 题和 2000 个资源文件。
- 只接受普通文件，拒绝加密文件、链接、重复路径、额外文件、无效引用和损坏资源。
- 预览有效期 15 分钟，绑定上传管理员；取消、完成、过期后清理。进程异常退出留下的暂存目录也按过期时间清理。
- 数据写入位于同一事务中，失败时回滚并清理已复制的资源。重复确认同一预览不会创建多个副本。

API 在 `DATA_DIR/transfers` 流式暂存文件，最多并行处理两个包，最多保留四个预览。Nginx 在接收大包前校验管理员身份，上传缓存使用已有磁盘卷，不占用 `/tmp` 的 64 MiB 内存盘。未改变部署端口与靶机资源配额。

## 接口

所有接口要求管理员身份，写入接口沿用 Origin 与 CSRF 检查。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/challenges/:id/export` | 导出题目 ZIP |
| GET | `/api/admin/contests/:id/export` | 导出比赛 ZIP |
| POST | `/api/admin/transfers/preview?kind=challenge` | 上传题目包并预览，multipart 字段为 `file` |
| POST | `/api/admin/transfers/preview?kind=contest` | 上传比赛包并预览 |
| POST | `/api/admin/transfers/:token/commit` | 提交 `title`、比赛 `starts_at` 及按原题目/小题 ID 索引的 `flags` |
| DELETE | `/api/admin/transfers/:token` | 取消预览 |

操作流程参考 [CTFd 导出与导入](https://docs.ctfd.io/docs/imports/overview/) 的管理入口和文件包形式，采用本项目的独立新条目导入策略。压缩包读取使用 [yauzl](https://github.com/thejoshwolfe/yauzl) 的惰性条目与流式读取接口。
