# 基础管理

## 页面与数据

后台首组为「基础」，依次提供概览、系统配置、容器策略、邮件策略、AI 转发。概览以总量、最近 7/30 天提交趋势、资源占用、最近异常组织信息。数据来自数据库和 Worker 心跳，不伪造主机 CPU 利用率；资源数显示已分配配额。

系统名称、页脚文本与链接存入数据库并用于前台。设置分区独立保存、审计，SMTP 密码和上游密钥用 APP_SECRET 派生密钥进行 AES-256-GCM 加密，不返回明文。修改 APP_SECRET 前必须迁移这些凭据。

## 容器策略

默认时长用于继承平台配置的独立靶机。题目可以单独覆盖时长；公共靶机、后台测试环境和 AWD 保持自身生命周期。续期次数和每次增加时长在创建时保存到实例，新设置不缩短已有环境。续期从当前到期时刻累加，并受比赛或答题阶段截止时间约束。

自动销毁旧实例默认关闭。开启后，创建受限时按时间选取同一范围、同一所有者的普通独立靶机。启动前列出将被销毁的题目，确认时重新计算，不接受任意实例 ID。公共靶机、AWD、附件、其他用户和其他比赛实例不被替换。旧实例完成清理后才允许新实例运行；排队仍占用名额。关闭弹窗不修改环境。

## 邮件策略

邮箱白名单支持完整邮箱和域名，域名精确匹配，子域必须显式使用 `*.example.com`。留空允许所有邮箱。验证开启后，注册先通过计算验证发送验证码，再用一次性验证码创建账户。验证码有效 10 分钟，最多尝试 5 次，发送有邮箱、IP 和全局限流。既有账户不被追溯封禁。

SMTP 支持 TLS、STARTTLS 和显式无加密模式，默认验证证书。测试连接只握手和认证；测试发信必须由管理员点击并指定地址。未配置可用服务器时不能开启邮箱验证。验证码和邮件内容不写入审计或请求日志。

## AI 转发

每条路由配置名称、上游协议、基础地址、加密密钥、模型映射及调用限额，独立启用、停用、轮换访问密钥。新建和编辑使用独立页面。转发访问密钥只在生成时显示，数据库仅存摘要。调用不使用浏览器会话鉴权，不向上游转发 Cookie、调用方 Authorization 或任意请求头。

对外提供 `/api/ai/:route/v1/chat/completions` 和 `/api/ai/:route/v1/messages`，以及模型列表。支持文本、工具调用、流式响应与两种协议转换；超出支持范围的请求明确返回 400。设置模型别名避免调用方任意选择上游模型；限制请求大小、输出 token、超时、RPM、每日次数和并发数。客户端断开时取消上游请求，不记录提示词、回复或密钥。只保存调用状态、耗时与 token 用量。

## 配置教程

### 系统信息与概览

1. 打开管理中心，默认进入「概览」。7 天与 30 天切换会同时更新新增用户、提交趋势和 AI 调用统计。
2. 资源占用是已预留的容器名额、CPU 和内存配额，包含排队与清理中的任务，非主机实时利用率。Worker 心跳超过 60 秒显示未连接。
3. 在「系统配置」保存系统名称、页脚文本和可选链接。名称用于导航、首页、登录注册和浏览器标题；页脚保留既有状态入口。文本按纯文本显示，链接仅允许 HTTP/HTTPS。

### 靶机时长与替换

1. 在「容器策略」配置默认时长、续期次数和每次增加时长。页面以分钟输入，API 使用秒。默认值为 30 分钟、7 次、每次增加 30 分钟。
2. 编辑题目的容器配置，可关闭「使用平台默认时长」并单独填写有效时间。旧题目原本的 1800 秒视为继承默认；已有非默认时长保留为覆盖值。
3. 开启「自动销毁旧实例」后，选手在数量、CPU 或内存达到上限时启动另一道题，会看到旧靶机列表。选择取消不改动环境；确认后先清理旧实例，新实例保持排队直至清理成功。
4. 自动替换仍受比赛配额和 60 秒操作冷却约束，不能突破设为 0 的上限，也不替换尚在冷却中的实例。如果自身可释放的资源不足，保留原环境并显示资源管理入口。

### 注册邮箱验证

1. 在「邮件策略」填写发件服务器、端口、加密方式、用户名、密码/授权码和发件邮箱。465 通常使用 TLS，587 通常使用 STARTTLS；以服务商配置为准。
2. 保存后点击「测试连接」验证连接及认证。需要检查投递时，填写收件邮箱并点击「发送测试邮件」。测试使用已保存配置，不会自动发信。
3. 配置邮箱白名单，每行一个邮箱或域名。`example.com` 不包含子域，`*.example.com` 只允许子域；需要同时允许两者时填写两行。
4. 开启「注册时验证邮箱」。选手完成计算验证后发送验证码，填写收到的 6 位验证码再注册；无需在正确验证码步骤重复计算验证。重新发送需要重新计算验证，服务端限制同邮箱每 60 秒一次、同 IP 每小时 10 次、全站每日 1000 次。
5. 关闭验证不会解除白名单。旧用户仍可登录，后续注册才受新策略约束。SMTP 密码留空保留原值，开启「清除已保存密码」会清除，填写新密码优先替换。

### AI 路由与靶机调用

1. 打开「AI 转发」，选择「添加路由」。填入上游协议、基础地址、密钥和模型映射。上游基础地址须包含供应商版本路径，例如 `https://api.example.com/v1`；不包含 `/chat/completions` 或 `/messages`。
2. 模型映射左侧是靶机调用的名称，右侧是上游实际模型名。可以添加多个模型；未列入映射的模型不能调用。
3. 配置每分钟次数、每日次数、并发、最大输出 tokens 和超时，开启转发并保存。访问密钥仅显示一次，只用于当前路由。上游密钥与转发访问密钥不同。
4. 编辑页分别给出 OpenAI、Anthropic 的 SDK 基础地址；前者以 `/v1` 结尾，后者不带 `/v1`。二者的 HTTP 请求路径如下，均要求独立的访问密钥：

```text
POST /api/ai/<路由ID>/v1/chat/completions
Authorization: Bearer <访问密钥>

POST /api/ai/<路由ID>/v1/messages
x-api-key: <访问密钥>
anthropic-version: 2023-06-01
```

OpenAI 请求示例：

```json
{"model":"contest-model","messages":[{"role":"user","content":"Hello"}],"max_tokens":256,"stream":true}
```

Anthropic 请求使用相同字段示例；系统提示放到顶层 `system`。路由根据上游协议转换文本与工具历史、流式 delta、结束原因和使用量。跨协议支持文本、工具调用、温度、top_p、停止序列；多模态、扩展思考、批量、Responses、工具并行交错、供应商特有参数及工具执行不在转换范围内，不能转换的内容会报错，不伪装成功。同协议转发保留请求功能字段，并统一限制模型与输出 token。

将基础地址、访问密钥和模型名放在靶机服务端配置，不把上游密钥交给选手。当前独立靶机为非 root、只读文件系统；程序可以从题目镜像已有的配置入口读取上述值。平台不自动修改镜像或放开网络策略。路由地址必须能从靶机网络到达。

停用或重置密钥会阻止后续请求，已经开始的调用可继续结束。每次请求只调用一个上游，不进行可能重复计费的自动重试。每日调用限额按 UTC 日期，失败尝试也计入次数；调用元数据保留 90 天。测试连接只查询上游模型目录，不发起模型生成；部分兼容服务不提供模型列表时可能返回 404，仍需按服务商接口验证生成调用。
