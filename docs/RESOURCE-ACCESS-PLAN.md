# 资源、流量与管理权限

## 本次实现范围

- 后台资源表直接显示访问地址、所属战队/用户，复用复制与打开操作。
- 错误 Flag 原文加密保存，仅通过有权管理提交日志的接口解密；旧记录显示未记录，不尝试还原。普通提交记录与公开动态不返回原文。
- 更新战队邀请码后使用只读输入框，保留首尾，中间掩码，复制仍复制完整值。
- 普通动态 Flag 绑定比赛、题目/小题和资源所属者。比赛队内共享资源，沿用战队维度；练习按用户。重建和资源到期不撤销 Flag，首次使用的模板保持固定。AWD 继续按比赛轮次轮换。
- 监测同时支持统计与 PCAP。管理员可配置采集开关、比赛范围、保留时间及容量。统计后台定时采集，页面读取汇总；抓包在靶机独立网络命名空间执行，覆盖端口与域名入口，按靶机所属战队归档。来源身份仍需结合 PCAP 和提交日志判断。
- 超级管理员保留完整权限，普通用户保持现有参赛功能；自定义角色可组合功能权限，另可授予指定题目或比赛的管理权限。后端逐请求检查权限，列表查询限制在授权范围内，角色或授权撤销立即影响后续请求。

## 约束

不将普通角色提升为全局管理员来绕过既有检查。角色与授权操作需要独立权限，避免自我提权与删除最后一名可用超级管理员。抓包不改变安全组、端口规则或靶机网络隔离。采集任务限并发、限文件大小、限总容量，并在靶机停止或配置关闭后停止；下载校验权限和归属，不暴露存储路径。后台继续使用现有表格、Switch、Tabs 与独立编辑页。

## 管理员操作

### 角色和单独授权

1. 在「管理中心 → 角色与权限」新建角色，按功能开启查看或管理权限。管理权限包含查看。
2. 在「管理中心 → 用户」点击权限图标，选择基础角色，勾选一个或多个附加角色。
3. 在同一页搜索题目或比赛，添加单独授权。题目授权包括查看、管理；比赛还可单独授予流量查看下载、采集管理。
4. 保存后立即作用于后续 API 请求，管理动态连接在下次检查/推送时关闭。角色删除同时撤销通过该角色获得的权限，其他角色或单独授权仍有效。

只有超级管理员可以创建角色、分配权限、修改超级管理员身份。迁移保留现有管理员账号，并在界面中明确显示为超级管理员。禁止停用或降级最后一名可用超级管理员。角色权限按并集计算，没有“拒绝覆盖”规则；题目权限不包含所属比赛的管理权限，比赛权限也不授予题库编辑权限。单独授权不能创建新的题目/比赛；新建需要对应功能的全局管理权限。比赛导入会同时新建题目，因此需要比赛和题目的全局管理权限。

查看权限可读取该功能的管理数据，不等于选手公开视图。例如比赛查看包含报名资料、内部提交与作弊线索；抓包查看包含 PCAP 下载。只有流量权限时，比赛管理显示流量入口，不开放其他管理页。全局流量管理才能修改采集策略，单场采集管理只能更改该比赛的模式。

### 流量策略

「管理中心 → 流量监测 → 采集策略」配置全局开关、默认抓包、采样间隔、保留天数、每靶机容量、总容量、采集并发、单包截取长度。「比赛 → 管理 → 流量监测」可选沿用全局、关闭、仅统计、统计与抓包。全局关闭优先于比赛设置。

默认仅统计，每 15 秒采样，分钟聚合；默认保留 7 天，每靶机 64 MiB，总计 2 GiB，最多同时采集 8 个靶机。设置保存后在下一采样周期生效。统计计入比赛私有容器的网络收发量，覆盖端口直连和域名代理。公共靶机不具备独立战队归属，不纳入此视图；附件生成任务和个人终端也不纳入比赛靶机流量。

采集随靶机运行，停止、到期、关闭策略会停止抓包并封存文件。每个 PCAP 以完整数据包为边界，约 4 MiB 或 60 秒封存一次；未封存文件不提供下载。每靶机按容量和最多 127 个封存文件滚动保留，容量不足时删除该靶机最旧文件。全局容量按文件大小和活跃采集的预留容量计算；新采集超额显示等待或容量已满。降低全局容量会清理最旧的封存文件并减少采集。已有文件按保留期限清理，不因销毁靶机立即删除。

每个采集容器上限 0.1 CPU、64 MiB、16 PID，计入平台全局 CPU/内存预算，避免挤占靶机额度。统计并发为 4，采集另有限并发；文件索引批量写入，页面和 PCAP 列表均每页 10 条。重流量可能因采集 CPU 或系统缓冲区限制丢包，本功能不保证无损全流量镜像。总收发量取自 Docker 网络统计，不依赖 PCAP 文件数量。

PCAP 按目标靶机归属战队分类，不代表数据包全部来自该战队。跨队攻击、共享出口、域名代理等场景应结合源地址、提交日志和 Flag 来源记录判断。TLS 加密内容不会自动解密。

### Flag 和提交日志

动态 Flag 的首次模板绑定持久保存在数据库，之后重建、续期、到期和修改题库模板不改变该队伍该题的已绑定值。多 Flag 题按小题 ID 独立绑定；环境变量仍按题目设置注入。不同队伍、题目、小题或比赛相互隔离。AWD 轮次 Flag 仍按原有轮次规则生成和失效，防止破坏对抗赛判题。

迁移会从历史环境快照回填模板，保留已有 Flag 指纹，兼容已发放的历史值。备份时必须同时保存数据库和 `APP_SECRET`；更换密钥会改变动态 Flag，并使旧错误 Flag 日志无法解密。错误 Flag 日志从本版本开始加密保存原文，历史记录显示“未记录”；正确提交不额外保存原文。普通用户提交列表、公开动态和观赛接口不返回原文或密文。

## 部署

先构建采集镜像，再更新 API 和 Worker：

```sh
docker build -t nebuctf/traffic:local deploy/traffic
docker compose up -d --build
```

可通过 `.env` 的 `TRAFFIC_IMAGE` 指定私有仓库镜像。Compose 创建 `nebuctf_traffic` 卷，Worker 读写 `/captures`，API 只读。每个采集容器仅挂载自己的实例子目录，通过 `NetworkMode=container:<靶机>` 共享该靶机网络空间，不挂载 Docker socket、宿主机目录或其他靶机抓包目录，不开启 privileged 或 host network。保留 `NET_RAW` 以及 tcpdump 降权和正常停止所需的 `SETUID/SETGID/KILL`，不授予 `NET_ADMIN`。

运行时使用 Docker API v1.45 的 volume subpath；须使用支持该能力的 Docker Engine。部署前应备份 PostgreSQL，迁移 31–33 由应用启动时在数据库锁内执行，可重复运行。此次更新无需增加对外端口，也不修改安全组。
