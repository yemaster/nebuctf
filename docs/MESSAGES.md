# 消息中心

用户入口为顶部铃铛、账户菜单中的“消息中心”，也可直接访问 `/messages`。后台入口为“基础 → 系统消息”。

## 收件箱

- 系统、比赛、提醒三类消息，每页 10 条，支持搜索、未读筛选和归档查看。
- 点击整行打开消息详情，成功读取后标为已读；可重新标为未读、归档或移回收件箱。
- 消息内的按钮进入对应比赛、报名审核或 WriteUp 页面。所有跳转限定为站内路径。
- “全部已读”处理当前分类中、列表读取时间之前收到的未归档消息；后到的新消息仍为未读。
- 未读数通过 WebSocket 更新，多个标签页共享已读和归档状态。连接中断时退避重连，并每 30 秒补查摘要；回到页面时重新同步。后台标签页关闭连接以减少占用。

## 自动通知

| 事件 | 接收对象 | 操作入口 |
| --- | --- | --- |
| 报名提交、自动通过或取消 | 相关战队成员 | 比赛概览 |
| 新的待审核报名 | 未禁用的管理员 | 比赛报名审核 |
| 报名审核通过、拒绝、暂停、恢复或组别调整 | 相关参赛成员 | 比赛概览 |
| WriteUp 通过或要求修改 | 对应参赛成员 | WriteUp 提交页 |
| 比赛开始前 15 分钟 | 已通过审核的正式参赛成员 | 比赛概览 |
| WriteUp 截止前 1 小时，且提交窗口已开放 | 未提交或需要修改的正式参赛成员 | WriteUp 提交页 |

比赛已有冻结名单时，消息以 `contest_members` 为准；后来加入当前战队的用户不会获得旧比赛的审核内容。尚未形成参赛名单的报名通知使用当前成员。禁用账号不接收新消息。

审核通知与审核操作在同一事务中保存，操作失败不会留下消息。重复保存相同审核状态和说明不会重复提醒。定时任务每 30 秒扫描一次，在提醒窗口内为新符合条件的用户补投递；同一用户不会重复收到同一场比赛、同一时刻的提醒。系统重启可恢复扫描，不补发已过期的提醒或历史审核结果。

## 发送系统消息

1. 在后台“系统消息”选择“发送消息”，进入独立页面。
2. 选择指定用户、比赛战队或全体用户。指定用户支持用户名或邮箱，每次最多 100 位；比赛支持搜索和分页选择，只发送给审核通过的正式参赛成员。
3. 填写标题、正文，可选站内链接和按钮文字。正文为纯文本，保留换行，不执行 HTML。
4. 发送后返回记录列表，查看接收人数、已读人数、发送人和时间。点击整行可展开正文。

消息接收对象按发送时刻确定，新注册用户不补收历史群发。请求使用幂等标识，网络重试不会重复发送。已发送消息不能编辑；内容有误时可撤回后重新发送。撤回保留管理记录，接收用户不再能读取内容。发送和撤回均记录审计日志。

## 存储与部署

迁移 29 新增 `notifications` 和 `notification_recipients`。正文共享存储一次，已读、归档状态按用户保存；收件箱、归档、未读统计和版本查询各有索引。列表只返回摘要，打开详情时读取完整正文。

API 进程运行定时提醒，并通过现有 PostgreSQL 通知通道触发 WebSocket 更新。推送只包含当前用户的未读数与版本标识，不包含正文；推送前批量复核会话和账号状态。每个用户最多 4 个连接，使用心跳、背压限制和断线清理。无须新增服务、端口或环境变量；Nginx 沿用 `/api/` 的 WebSocket 转发。

界面参考 [shadcn 收件箱示例](https://ui.shadcn.com/view/new-york-v4/sidebar-09)、[Item 组件](https://ui.shadcn.com/docs/components/radix/item)和 [GitHub 通知收件箱](https://docs.github.com/en/subscriptions-and-notifications/how-tos/viewing-and-triaging-notifications/managing-notifications-from-your-inbox)，继续使用项目现有的 Tabs、Item、Sheet、Switch、Tooltip 和分页组件。
