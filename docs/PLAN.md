# NebuCTF 实现方案

设计日期：2026-10-22。目标：可自托管、可审计、以安全和性能为优先的 Jeopardy CTF 平台。

## 1. 参考与取舍

| 官方资料 | 采用的功能设计 | 本项目的取舍 |

## 2. 功能与验收范围

### 首版必须实现

- 账号：注册、登录、退出、当前身份、修改密码；管理员通过 CLI 初始化，禁止默认管理员密码。
- 战队：创建、邀请码加入、成员列表、队长轮换邀请码、退出；报名后锁定成员以防比赛身份漂移。
- 题库：分类、搜索、难度、分页、解题状态、题面、提示、提交记录；静态及动态 flag。
- 比赛：创建/编辑、发布时间、起止时间、报名、战队上限、赛题关联、公告、动态积分、封榜、榜单。
- 资源：静态附件上传/下载；个人或战队独立动态附件生成；公共容器；个人/战队动态容器；创建、查看、续期、销毁、到期回收。
- 管理：题目和比赛 CRUD（软下线保留审计）、附件上传、公告发布、全局资源视图、强制回收、提交记录、审计日志。
- 部署：Docker Compose、健康检查、数据卷、反向代理、环境变量样例、备份/恢复说明。
- 验收：身份与越权、CSRF、竞赛窗口、重复提交、积分与封榜、配额与资源任务、前端构建和真实浏览器检查。

### 后续扩展，不伪装成已实现

邮箱验证/找回、MFA/OIDC、报名审批、付费提示、解题报告审核、流量捕获与反作弊分析、Kubernetes/多节点调度、对象存储/CDN、实时推送、AWD/靶机攻防模式。首版保留常规轮询和分页 API。

## 3. 架构

浏览器 → Nginx（同源 /api、请求体与速率限制）→ Fastify API → PostgreSQL。
Worker 轮询 PostgreSQL 中资源状态，通过 Docker API 创建/回收题目容器和生成附件。
API 挂载附件卷，Worker 挂载同一卷；仅 Worker 能访问 Docker Socket。生产建议 Worker 使用专用靶机主机或隔离 VM。

- Monorepo：apps/api（HTTP、领域逻辑、SQL、Worker）、apps/web（React、TypeScript、shadcn/ui）、deploy、examples、scripts、docs。
- PostgreSQL 为唯一持久状态来源，使用参数化查询、连接池、外键、唯一约束、索引、事务和行锁。
- 无 Redis 强依赖，减少首版运维复杂度。敏感操作采用数据库原子限流，多副本一致；边缘请求限流由 Nginx 承担。
- 本地开发/测试支持 PGlite（真实 PostgreSQL WASM），生产强制 PostgreSQL。PGlite 不承担多进程 Worker 调度验收。
- 不承诺未经压测的并发数字；交付可复现的检查和基准测试。

## 4. 数据模型与一致性

users、sessions、teams、memberships、contests、registrations、challenges、contest_challenges、submissions、solves、attachments、instances、announcements、audit_logs、rate_limits。

- 用户最多加入 20 支战队，同一比赛只能代表其中一支；成员变更与报名共用数据库事务级咨询锁。
- 比赛成绩归报名时锁定的战队；练习归用户；(赛场, 题目, 解题主体) 唯一。
- 静态 flag 仅存 HMAC；动态 flag 从密钥、题目、赛场、主体派生，跨队不可互用。更换密钥会使已有 flag 失效。
- 提交不存 flag 明文。题目 API 使用字段白名单，绝不返回 flag、镜像配置和内部错误。
- 动态积分按当前解题数实时聚合；封榜同时冻结解题集合和计分人数，避免通过分值泄露赛后/封榜后解题。
- 题目与资源快照在入队时固定。带历史解题或活跃实例的题目禁止修改判题/资源核心配置。

## 5. 安全边界

- Argon2id 密码哈希；随机高熵会话仅存哈希，HttpOnly、SameSite=Lax、生产 Secure；改密撤销所有会话。
- 所有写请求验证 Origin 与 CSRF 请求头（包括登录）；严格输入 schema、长度和 body 上限。
- IP 登录限流、账号登录限流、主体提交限流、资源创建限流；失败时不泄露账号存在性。
- RBAC：匿名、用户、管理员；每次请求校验会话和用户状态；附件和实例每次校验比赛窗口及归属。
- 题面和教程使用禁原始 HTML、过滤危险 URL 的 Markdown；CSP、防 MIME 嗅探、禁止嵌入、私有 API 禁缓存。
- 上传文件以 UUID 存储，不信任原始路径；下载强制 attachment，限制单文件 20 MiB。
- 日志不记录 cookie、密码、flag、邀请码；管理员变更写审计。

## 6. 资源生命周期

状态：queued → starting → running / ready；错误 → failed；停止/到期 → stopping → stopped。
调度操作采用数据库锁；starting 超时重入，Docker 名称幂等。Worker 通过 SKIP LOCKED 领取任务，starting 超时后回收任务租约，重启检查遗留资源。

- 全局实例数/CPU/内存、主体实例数、单题 CPU/内存/PID、TTL、最大续期累计时长均校验。
- Docker：镜像前缀白名单、禁止自动拉取未知镜像、非 root UID、cap-drop ALL、no-new-privileges、只读根、受限 tmpfs、有限日志、无挂载、无 privileged/host network。
- 附件生成：network=none，超时停止，只接受 /output/artifact.zip 中单一普通文件、大小限制、不解包到宿主目录。
- 在线题目：每实例独立桥接网络；端口由 Docker 分配。公网访问主机和绑定地址由部署配置指定。桥接网络本身不阻断宿主/公网出口，生产必须在专用靶机节点配置出口 ACL；文档明确此边界。
- 公共容器按题目+赛场共享，只有管理员启动/停止；动态容器按主体隔离。
- 资源配额预约与实例插入在同一全局事务锁内，失败/停止释放。

## 7. 前端信息架构

顶部主导航：练习、比赛、题单、排行、学习；账户菜单包含战队、靶机和管理入口。首页展示公告、近期比赛、日历和实际解题动态。进入比赛后顶部替换为比赛菜单，左侧提供「返回大厅」，右侧保留账户。未报名用户隐藏赛题/靶机入口，开赛前和结束后隐藏赛题。比赛详情集中显示时间与报名操作，海报分栏，下方为规则和组别。普通导航轻量淡入，比赛卡片展开为完整详情，作答及表单不做整页位移。
练习默认展示分页目录，选择题目进入全屏工作区；比赛使用独立全屏赛场。题面连续排列正文、附件、环境、提示和提交。管理表单按业务拆分。
无营销副标题、装饰口号、伪数据；开发示例数据只能通过显式 seed 命令装载。

## 8. 实现顺序

1. 固化方案和 schema；2. 身份/战队/题库/比赛领域服务；3. 资源 Worker 与附件；4. 管理 API；5. shadcn/ui 前端；6. Docker/样例/运维文档；7. 集成测试、安全回归、构建、浏览器检查。

## 9. 学习系统（用户追加范围）

- 知识库与教程：分类、搜索、Markdown（禁原始 HTML）、代码块、发布/草稿、阅读完成标记。
- 技能树：多条路线、节点前置依赖、关联文档和练习题、完成状态与路线进度。
- 完成规则：节点的文档已标记完成且关联题目已有个人练习解题；前置节点全部完成后解锁。没有关联项的节点禁止保存。
- 图结构保存时检查缺失依赖、自依赖与环；进度派生计算，无需维护易漂移的缓存计数。
- 管理中心增加文档编辑与技能路线配置。读取和完成接口按发布状态鉴权，草稿不暴露给普通用户。

## 10. 靶机双入口（用户追加范围）

- 每道容器题独立选择 `port` 或 `domain`；同一赛事可混用。
- 端口模式提供单 TCP 端口映射；域名模式使用 UUID 泛域名，经独立 HTTP/WebSocket 网关进入实例 internal 网络，不暴露题目宿主端口。
- 网关仅根据数据库中运行且未过期的实例路由，限制私网 IPv4 和非特权上游端口，剔除平台会话与伪造转发头；网关没有 Docker Socket。
- TLS 在外部反向代理终止，生产需独立靶机域、泛解析和通配符证书。当前不支持任意 TCP/SNI、UDP 或多端口映射。
- Worker 使用 PostgreSQL 会话锁选出单调度器，最多并行创建 4 个环境，回收循环独立推进；域名网关重建后自动重新接入实例网络。
- 动态附件通过固定非特权 exec tar 命令采集运行时 tmpfs，严格验证 Docker 帧与单文件归档，保留只读根和无网络限制。

## 11. 多小题、题单与比赛工作流

新增 `challenge_parts`、`part_solves`、`problemsets`、`problemset_items`、`contest_groups`，注册记录关联组别，比赛关联海报。迁移保留传统单 Flag 题及其解题记录；新小题计分与整题完成分开存储，唯一约束与事务锁保证并发重复提交只获得一次进度。积分按各小题独立衰减，完整解题记录继续服务于题单和技能树。

练习目录与题单详情均每页 24 题，支持搜索、页码跳转。比赛列表采用海报和按时区聚合的日历；独立赛场继承练习工作区。报名选择队长管理的战队和管理员预设组别，同一成员的重复报名在事务内拒绝。

错误通过可选 action 字段提供站内下一步入口；实例启动、专属附件生成、续期和销毁显示持续活动进度，确认完成后退场；下载仅显示按钮状态。注册密码最低 8 位。具体约束与接口见 API 和出题文档。


## 12. 后续设计参考约束

清华 CTFy（https://ctfy.tsinghua.edu.cn/）加入功能流程和布局参考，重点关注按身份/赛事状态组织导航、分页筛选、题目与环境操作的衔接。具体观察与访问限制记录在 FRONTEND.md。

用户明确要求保持当前 NebuCTF UI 风格：视觉细节继续使用现有 shadcn/ui、Lucide、默认字体、明暗主题、精简文案与现有信息密度。参考站的外观不作为改版目标。既有单行比赛导航、比赛直接作答、独立后台编辑页与可手动调整的树形技能树继续保留。
