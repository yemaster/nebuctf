# 性能与加载

## 2026-10-28 优化

题目目录只读取列表字段，不再从数据库传输题目正文、Flag 配置及完整环境配置。小题解题统计、三血按题目集合聚合；排行榜先按参赛者汇总正向得分，再与扣分账本合并，分页解题记录只聚合一次。分数仍实时计算，没有添加可能过期的成绩缓存。

首页、账户、认证、题库和比赛内容分别按需加载。题库侧栏与答题区域使用独立加载边界，翻页或加载题面不会清空输入。编辑器、PDF、3D 和图表不进入首页或普通列表的静态依赖。普通读取请求随页面离开取消，权限与参数错误不再自动重试。

构建时预生成 gzip；Nginx 优先返回预压缩静态资源，JSON 使用低压缩级别。带版本号的静态文件缓存一年，HTML 入口与主题初始化脚本要求重新验证。AI 流式转发关闭压缩，保留逐段响应。

## 接口对照

在远程 PostgreSQL 17 的独立临时数据库执行，100 名用户、100 支战队、80 道题、120 个小题，练习与比赛合计 16000 条整题解答、24000 条小题解答。题目正文约 19.5 kB，小题正文约 5 kB。旧版与新版使用相同数据和 API 容器资源配置；每条接口先预热一次，再顺序执行五次，取中位数。时间为应用注入请求的完整处理时间，不含公网传输。

| 接口 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 练习题库（兼容的默认 24 条） | 25.74 ms | 15.75 ms |
| 比赛题目目录（80 题） | 1322.76 ms | 93.92 ms |
| 练习排行榜 | 925.71 ms | 247.28 ms |
| 比赛排行榜 | 1170.43 ms | 291.21 ms |

练习题库的数据库结果序列化体积从 775482 字节减少到 22818 字节，比赛目录从 2463349 字节减少到 156709 字节。`EXPLAIN (ANALYZE, BUFFERS)` 用于确认重复扫描和重复 JSON 聚合消除。四个接口剔除时钟与新增分页元数据后的响应逐项一致；权限、封榜、提示扣分和轮次计分另由回归测试覆盖。

这些数字说明同一夹具下的改进，不表示正式比赛容量。没有增加生产 CPU、内存、连接池或 Worker 并发数，也没有修改端口及网络策略。

## 构建检查

```sh
npm run build
node scripts/check-web-performance.mjs
```

检查入口、首页、登录、比赛列表和练习列表的完整静态依赖闭包，拒绝意外引入编辑器、PDF、3D、图表或流程图库；每页压缩后 JS/CSS 预算为 400 kB，并逐个解压验证资源一致性。该检查已加入 CI。此次构建首页约 287 kB、登录约 266 kB、比赛列表约 289 kB，不包含之后主动打开的重型功能。

只读部署烟测可使用已有 `BENCH_ORIGIN=... BENCH_REQUESTS=50 BENCH_CONCURRENCY=2 npm run benchmark`。限流、错误响应不能作为有效吞吐量。容量评估仍需接近正式参赛规模的独立环境与持续负载。

实现参考：[Vite 代码分割](https://github.com/vitejs/vite/blob/main/docs/guide/features.md)、[Nginx 静态 gzip](https://nginx.org/en/docs/http/ngx_http_gzip_static_module.html)、[Nginx 响应压缩](https://docs.nginx.com/nginx/admin-guide/web-server/compression/)、[PostgreSQL EXPLAIN](https://www.postgresql.org/docs/17/using-explain.html)。
