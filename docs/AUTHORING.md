# 出题与学习内容教程

## 发布练习题

1. 管理中心 → 题目 → 新建题目。
2. 填写名称、分类、难度、题面和提示。
3. 选择客观题、CTF、AWDP 或 AWD；答案/Flag、靶机和附件分别配置。
4. 设置积分与资源限额，按需勾选「开放练习」及「启用」。定时上线在比赛的「赛题设置」中设置，AWD 仅用于比赛。
5. 保存后在题目编辑页的附件区上传文件，也可使用题目列表的上传按钮；单文件最大 20 MiB。

题面、知识库与教程支持安全 Markdown，禁用原始 HTML 并过滤危险链接。Flag 严格区分大小写且保留空格；平台不存提交的 flag 明文。管理员账号可以正常提交并参与计分；练习按个人计分，比赛按已报名战队计分。

有解题或正式活跃环境后，不能修改判题、镜像、资源与积分核心字段；创建新版本题目。编辑时 Flag 留空表示保留原值，不会把旧值返回浏览器。

## 动态 Flag 模板

题目编辑 →「Flag 与计分」→ 选择「动态 Flag」，填写模板并点击「预览」。保存后可启动测试靶机验证。新建题目默认 `flag{[GUID]}`；已有题目留空继续使用原来的 `flag{40 位十六进制}`，不会改变已分发的答案。

| 模板 | 效果 |
| --- | --- |
| `NebuCTF{[GUID]}` | 自定义前缀和 UUID |
| `NebuCTF{web_[TEAM_HASH]}` | 固定文本和 12 位战队专属标识 |
| `NebuCTF{welcome_to_the_security_challenge}` | 自动进行 Leet 字符替换 |
| `[LEET]NebuCTF{hello_world_[TEAM_HASH]}` | 同时使用字符替换和战队标识 |
| `[CLEET]NebuCTF{hello_world_[TEAM_HASH]}` | 字符替换也允许特殊符号 |

前缀保留原样，只有花括号内的内容参与替换。模板及生成结果最多 256 字符；变化空间至少 32 bit，短模板可加入 `[GUID]` 或 `[TEAM_HASH]`。预览是独立示例，不是任何选手的真实答案。语法参考 [GZCTF 动态 Flag](https://gzctf.gzti.me/guide/features/dynamic-flag)。

多小题各自可配置模板，留空沿用题目模板；即使模板相同，各小题仍生成不同的 Flag。模板与自定义环境变量映射一起用于靶机、专属附件和管理员测试环境。AWDP 的攻击小题可单独覆盖模板，防守检查器获得与被测环境相同的 Flag。AWD 在每轮写入新的模板 Flag，沿用现有文件注入与巡检流程。

Flag 按题目、小题、比赛和用户/战队稳定派生；同队成员共享答案，练习、比赛和测试环境互相隔离，重建普通环境不改变答案。`[TEAM_HASH]` 使用 NebuCTF 自身密钥派生，不兼容 GZCTF 的外部战队签名/盐值接口。含特殊符号的 Flag 应通过环境变量或文件读取，不要拼接进 Shell、SQL 或命令字符串。

有解题记录、正式活跃环境或待处理防守任务后，模板不能修改；需要更换时新建题目版本。静态 Flag 和客观题不使用模板。

## 四类资源

### 静态附件

为所有参赛者提供相同附件，设置静态 Flag。可以没有附件，仅题面答题。下载时检查身份和比赛权限，文件采用随机存储名，不直接暴露磁盘路径。

### 动态附件

每个用户或参赛战队生成自己的 Flag。生成器从环境变量 `FLAG` 读取它，把最终 ZIP 原子重命名为 `/output/artifact.zip`，随后保持进程存活，等待 Worker 采集并销毁容器。**不要生成后立即退出**：只读根模式使用 tmpfs，容器退出后 tmpfs 数据会消失。

```sh
docker build -t nebuctf/attachment-example:1 examples/dynamic-attachment
```

在题目中选择动态附件，镜像为 `nebuctf/attachment-example:1`。生成器无网络，只能写 `/tmp` 和 `/output`；60 秒内未出现完整产物即失败。产物最大 20 MiB。生成器镜像必须包含 `/bin/tar`（示例 Alpine 镜像已包含）。Worker 通过固定、非特权的 tar 命令读取运行时 tmpfs；输出帧、归档校验和、文件名和大小均严格验证，只接受单一普通文件，不提取任意路径、符号链接或额外条目。Docker archive/cp 不用于采集 tmpfs。

### 公共容器

所有参赛者使用同一个环境，按「题目 + 赛场」共享。管理员选择对应赛场后点击题目行的播放按钮启动；静态 Flag 需要由镜像本身提供，并在管理界面设置相同答案。平台不会把 HMAC 摘要当作 Flag 注入。

### 动态容器

每个练习用户/参赛战队独立环境。进程从 `FLAG` 环境变量获取答案。

```sh
docker build -t nebuctf/container-example:1 examples/dynamic-container
```

镜像例子监听 `0.0.0.0:8080`，访问 `/flag` 可取得自己的 Flag，仅用于验证环境隔离。容器必须能以 uid/gid `65534:65534` 运行，不依赖写根文件系统或特权 capability。建议镜像声明 HEALTHCHECK；Worker 最多等待 30 秒，健康后才提供入口，未声明健康检查的镜像以进程运行状态为准。示例包含健康检查。默认镜像前缀是 `nebuctf/`，环境启动只使用已就绪的本地镜像；管理员可以通过下述镜像管理功能显式拉取允许仓库内的镜像。

| 设置 | 端口模式 | 域名模式 |
| --- | --- | --- |
| 访问方式 | 宿主机端口 | 泛域名代理 |
| 题目服务 | TCP 或 HTTP | 明文 HTTP，可升级 WebSocket |
| 服务监听 | `0.0.0.0:内部端口` | 相同 |
| 展示入口 | `host:随机端口` | `https://UUID.labs.example.net` |
| 主机暴露端口 | 每实例一个 | 无；统一进入网关 |

两个模式共享 CPU/内存/PID、TTL、配额和回收机制。域名模式的 DNS、TLS 先按部署文档配置；仅选择模式不会自动购买域名或申请证书。

## 组织比赛

1. 在题库准备赛题。比赛选题可使用全部题型及练习题；已向练习场开放的题会明确标注，练习成绩不计入本场比赛。未公开的新赛题不要勾选「开放练习」。
2. 新建比赛，设置起止时间、队伍人数上限、可选封榜时间。
3. 在「赛题设置」的左栏搜索全部题目，按分类、题型筛选，每页 10 条；右栏按题目分类汇总全部已选赛题，显示各分类数量，可直接移除。翻页或搜索不影响已选题目。选题区默认展开，选完可收起；在赛题行直接启停、上移、下移或移除；展开该题就能设置上线时间及计分方式。多小题的分值和曲线逐项展示。修改统一点击「保存比赛」，保存后留在当前编辑位置。必要时发布比赛公告。
4. 在「报名分组」查看每页 10 组的摘要卡片，点击整张卡片进入组别配置，设置名称、说明和默认权限，包括报名、全局排名、查看、作答、资源、计分、三血及动态衰减。返回列表或切换标签会保留草稿，统一点击「保存比赛」生效。展开「单题权限」可覆盖后六项，默认沿用组别。首次报名后不能增删组别，开赛后锁定计分相关权限，详见 [组别权限](COMPETITION-RULES.md#组别权限)。队长选择自己的战队和对应组别报名；一个成员不能通过多支队伍重复参赛。报名后，成员在比赛结束前锁定。比赛开始前可取消报名解除该报名的约束。
5. 在比赛编辑「基本信息」中预览、上传、更换或移除海报，支持 PNG/JPEG/WebP，最大 5 MiB。海报操作立即生效，不会清空未保存的表单；新比赛先保存一次再上传。比赛列表也保留上传入口。公开比赛会显示在海报列表和比赛日历，赛题在独立全屏赛场展示。
6. 开赛后不能更改赛题集合、起止/封榜时间或人数限制；仍可编辑说明和发布状态。
7. 需要收集解题报告时，打开紧随「基本信息」的「WriteUp 提交」标签，选择「仅队长提交」或「队长和队员均可提交」，再设置提交开关、是否必交、允许替换、时间窗口、PDF/ZIP 格式、大小上限和要求，点击「保存比赛」。开始时间留空时从比赛结束开始接收，截止时间必填，单个文件最大 20 MiB。
8. 在比赛菜单「管理 → WriteUp 管理」按战队、组别和提交状态查看，每页 10 支队伍。每队共用一份报告，其他有权成员替换的是同一份文件。可筛选未提交队伍、下载或导出报告，点击「查看」进入独立处理页确认收件或填写修改意见。退回修改仍受截止时间限制；需要补交时先延长截止时间。

动态积分使用 CTFd 风格的抛物线衰减：`ceil(initial + (minimum - initial) × (solves / decay)²)`，不低于 minimum。题目当前分值应用到所有已解题队伍，同分按最后解题时间排序。

封榜会冻结榜单和题目公开解题数/分值，比赛结束后显示完整结果。练习得分不带入比赛，管理员与普通选手使用相同计分规则。禁用账户只撤销登录资格，不自动删除历史得分；违规判罚流程尚未实现。

## 文档与教程

管理中心 → 文档：填写标题、URL 标识、分类、类型和 Markdown 正文，可切换预览。原始 HTML 不渲染，链接使用 React Markdown 的安全 URL 策略，代码块保留原文。

用户可搜索、按类别和文档/教程筛选，登录后标记完成。首版没有阅读时长强制验证、测验引擎或付费访问。

## 技能树

管理中心 → 技能树：

1. 点击「新建技能树」进入独立编辑页，填写名称与学习目标。
2. 添加节点，每个节点至少关联一篇文档或一道练习题，也可以同时关联。
3. 在画布拖动节点排布，从前置节点底部连接点拖到后续节点顶部连接点。默认从上到下排列，根节点居中、同级分支展开；画布支持平移、缩放和显示全部节点。
4. 点击节点，在右侧设置名称并选择关联文档/练习。选中连线按 Delete 删除，或在右侧移除前置技能；删除节点会同时移除相关连线。自依赖、重复连线、循环依赖不能建立，服务端再次验证。
5. 选中节点可直接「添加子节点」，自动连接前置关系；点击「树形排列」按当前连线重新整理全部位置。已有手动坐标不会在打开页面时被覆盖。
6. 点击「保存」写入节点位置与连线，重新打开后保留布局；公开技能树的「作者布局」使用相同位置展示；默认「树形布局」根据依赖紧凑排列，便于逐支浏览。
7. 启用路线之前，先发布关联文档与练习题。

节点只有在全部前置节点完成后才解锁；关联文档需标记完成、关联题目需在个人练习中完成全部小题，两者均满足才完成。战队比赛成绩不用于个人技能进度。学习进度由实际数据计算，不依赖手工维护百分比。

解锁是学习路径引导，不是题库访问权限系统：用户仍可从公开题库提前练习，后续完成前置技能时相应进度会自动汇合。

## 一题多个 Flag

编辑题目时选择「多个小题」，添加 2–20 个小题，分别设置名称、说明、初始分和最低分。静态类型为每个小题设置不同 Flag。题面和资源由整题共享，选手在同一个输入框提交，系统自动匹配小题并独立计分；全部通过后整题才标记完成。

动态积分开关与衰减参数由整题共享，每个小题按自己的通过人数分别衰减。封榜同时冻结公开小题通过人数与积分，选手仍能看到自己的实际进度。已有部分解答后只能调整小题名称与说明，不能删除、重排或更换判题参数。

动态多小题的容器与附件生成器会收到：

| 环境变量 | 内容 |
| --- | --- |
| `FLAG_COUNT` | 小题数量 |
| 小题配置的变量名 | 默认 `FLAG_1` … `FLAG_N`，保存后绑定小题，重排不会交换变量对应的答案 |
| `FLAGS_JSON` | 小题 UUID 到答案的 JSON 对象 |
| `FLAG` | 第一个小题答案，方便兼容旧镜像 |

在「靶机配置 → Flag 注入」按行设置每个小题的变量名；只有附件生成器时在附件标签配置。变量名仅允许大写字母、数字和下划线，不能重复或占用系统保留名称。变量名修改后先保存，测试与正式实例使用同一份已保存映射。

每个小题的分数曲线与该小题设置并排展示，窄屏显示在设置下方，无需通过下拉框选择预览对象。

传统单 Flag 题默认使用 `FLAG`，可改为 `GZCTF_FLAG` 等名称并保留 FLAG 兼容别名，已有答案派生不变。多小题共享一个实例与配额，出题镜像需要自行把各答案放到对应解题步骤；仅使用旧示例镜像不会自动形成多阶段题目。静态 Flag 由镜像自行提供，不从摘要恢复明文；AWD 轮换 Flag 仍使用专用文件。可运行示例见 [单容器多 Flag](../examples/multi-flag/README.md)。

## 题单

管理中心 → 题单：填写标题、说明，搜索并选择题目，调整顺序后发布。每份最多 500 题，选择器和公开详情均支持分页。草稿题与未开放练习的题不会在公开题单中显示，也不计入公开进度。题单按整题完成统计，多小题需要全部通过。

## 参赛者操作提示

注册和修改密码最低 8 位，不强制大小写、数字或符号组合。用户可加入多支战队，但一次比赛只能代表一支战队；报名需由所选战队队长操作。组别用于分类、榜单筛选及权限控制，可由比赛或组别开启报名审核。管理员在比赛「管理 → 报名战队」核实成员并审批，未接入学校身份自动验证。

缺少战队、未报名、环境额度用完等提示附带操作入口。启动、生成专属附件、续期和销毁时显示持续推进的活动进度，服务端确认成功后完成并退场；下载不显示进度条，支持取消。正确提交显示成功动画；错误提交让输入框抖动并保留原文，全部小题完成后不再显示提交框。

资源到期由 Worker 自动回收，前端倒计时不承担清理责任。容器健康就绪、附件生成成功后开始单次 TTL，准备阶段有独立的 5 分钟期限。单次 TTL 为 60 秒至 2 小时；个人/战队实例累计上限 4 小时，公共实例上限 7 天；比赛资源不超过比赛结束时间。续期受这些上限约束，不能无限续期。

同一用户或战队在同一赛场对同一道题的启动/销毁、生成/删除共用 60 秒冷却，环境失败也不能立即连续生成。错误详情保留在 Worker 日志，参赛者只看到可操作的通用原因。我的靶机不显示公共容器；公共容器仍在对应题面使用。


## 后台操作与定时上线

管理中心采用分组侧栏：内容、赛事、运维。题目、比赛、题单、文档、技能树和公告的新建/编辑都进入独立页面，可直接访问、刷新或在新标签页打开。顶部面包屑显示当前位置，保存后返回原列表并保留搜索与页码。弹窗仅用于挑选关联内容或确认操作。

管理列表默认每页 24 条，支持搜索和页码跳转；题目额外支持分类、练习/比赛范围、发布状态筛选。题目行直接展示小题数、类型、分值、归属、状态和计划上线时间；比赛行展示起止时间、赛题数、报名战队数、人数上限、状态与封榜时间。

定时出题：先建未启用的赛题，预先关联到比赛，在题目编辑页选择「定时上线」并填写本地时间。保存后列表显示计划，API 在到期后约 2 秒内自动启用，比赛动态随之出现上线信息。服务停止期间不发布，恢复后补发；如需取消，改为「暂不启用」后保存。列表的启用按钮会立即发布并取消原计划。定时发布不会绕过比赛本身的开始时间、报名和访问限制。

## 拉取镜像与发布前测试

1. 打开题目编辑页的环境配置，填写允许仓库内的镜像地址。镜像未在 Worker 主机上就绪时，点击「拉取镜像」。
2. 弹窗显示各层下载、解压进度和日志。可以关闭窗口继续编辑，再从「拉取日志」查看结果；失败后重新点击「拉取镜像」重试。
3. 镜像就绪后点击「启动测试靶机」；动态附件题显示「测试生成附件」。新题先保存，已有题目测试使用当前表单的镜像、访问方式、端口和资源参数。
4. 靶机就绪后可以复制地址或点击跳转图标；附件就绪后直接下载。测试环境运行 10 分钟，可手动停止，启停间隔至少 60 秒。修改题目类型需先保存再重新测试。
5. 在「管理中心 → Docker 镜像」查看镜像是否就绪、大小、关联题目数和最近拉取日志，支持搜索、状态筛选和分页。资源页用「测试」标记测试环境。

测试环境与练习、比赛相互独立，支持未发布题目；它占用正常资源配额，但不会给比赛创建公共环境或计分。正式公共靶机仍从题目列表选择对应赛场后启动。

网页拉取当前采用匿名仓库访问，不保存仓库账号密码。私有镜像可由运维在 Worker 主机完成登录并预拉取，随后页面会自动识别；默认允许前缀仍为 `nebuctf/`，其他仓库由运维配置 `IMAGE_PREFIXES`。本地构建的镜像无需再次拉取。

## 题目编辑页的操作顺序

基础信息在顶部，填写名称、类型、分类和难度。主区先用 Markdown 编辑器填写题面与提示；随后设置单 Flag 或多个小题，再配置靶机/生成器和附件。右侧统一设置计分、启用状态、定时上线与是否开放练习。

- 多小题的名称与分值并排，说明和 Flag 位于同一小题内；使用上下箭头调整顺序。动态类型的 Flag 随环境生成。
- 固定积分仅使用分值，最低分与衰减项停用；多小题分别设置分值。
- 动态附件只展示生成器需要的参数；端口和访问方式只用于容器题。
- 新建题目保存后自动进入编辑页，继续上传附件和测试。已有题目保存后回到原筛选/分页位置。
- 在附件区查看文件名和大小，可以多选上传、下载或删除；删除需点击行内「确认删除」。管理员可操作未发布、未开放练习题目的附件。附件操作立即生效，与题目表单的保存分别执行。

切换题目类型、判题方式或题面预览时保留本页输入；离开页面前仍需保存。删除附件会移除平台文件及引用，无法通过撤销恢复。

### 编写 Markdown 题面

工具栏支持标题、粗体、链接、图片链接、引用、代码、列表与表格，选中文字后点击即可插入对应 Markdown。右侧三个显示按钮分别为编辑、分屏预览和预览；窄屏时分屏上下排列。可拖动底边调整高度，点击全屏图标专注编辑，Escape 或退出全屏图标返回。

支持常用编辑快捷键：Ctrl/⌘ + B 粗体、Ctrl/⌘ + I 斜体、Ctrl/⌘ + 7 编辑、Ctrl/⌘ + 8 分屏、Ctrl/⌘ + 9 预览。亮暗主题跟随网站，题面最多 20,000 字符。预览与答题页使用相同 Markdown 规则；HTML 不执行，不支持在题面内嵌脚本。图片工具插入图片 URL，题目附件仍通过下方附件区上传。

切换显示模式会保留原始 Markdown；保存题目才会写入服务端，没有自动保存草稿。


## 客观题、攻防题与混合比赛

客观题的单选、多选和填空答案在「答案与计分」配置；填空可为同一空设置多个可接受答案。攻击与防守题、补丁检查镜像、轮次积分和独立作答时间的完整步骤见 [比赛规则](COMPETITION-RULES.md)。

比赛编辑分为基本信息、赛题设置、时间规则和报名分组。上线安排和计分设置集中在对应赛题下方，计分方式直接显示为单选项。题型不限制比赛选题，题目分值可在当前比赛覆盖。提示使用独立条目编辑；在进行中的比赛新增提示后会通过 WebSocket 提醒选手。攻防示例及标准补丁打包命令见 [示例](../examples/attack-defense/README.md)。

题目管理列表每页 10 条，启用状态可直接用开关修改，保存期间阻止重复操作，失败后恢复原状态。比赛中的启用开关只修改本场安排，仍须保存比赛；题库未启用时，赛题列表会显示对应提示。

比赛菜单进入「比赛设置」后，标题返回按钮会回到进入前的比赛页面并保留筛选；后台比赛设置和管理页顶部另有「返回比赛」，可直接回到本场概览。报名战队列表点击队名展开成员，查看用户名、用户 ID、邮箱、队长/队员、账户状态和注册时间；「审核详情」保留独立编辑页。

## 设置私密比赛和资源上限

1. 打开比赛管理侧栏的「比赛设置」，进入「访问与报名」。
2. 选择公开或私密。公开比赛可设置不限、邀请码或指定战队参赛；私密比赛选择允许的战队，只有这些战队、已有有效报名的成员和管理员能看到比赛。
3. 按需设置排行榜、大屏、报名审核及赛后练习。公开/私密只控制可见性，未通过报名仍不能答题。
4. 在「资源限制」中分别填写靶机、动态附件的每队和全场上限。留空不附加限制，0 禁止新建，平台既有配额仍有效。
5. 保存比赛。调整数量不会关闭已有资源；名额包括排队、启动、运行、待释放及已经生成的动态附件。删除或到期清理完成后恢复名额。

例如每队靶机 1、动态附件 1，全场靶机 20、动态附件 30：队员共享本队名额，不会每人各获得一份配额。公共靶机只占全场名额，静态附件下载不占名额。AWD 自动分配环境也遵守比赛限制，设置时需为选用的 AWD 赛题预留足够名额。

已通过、待审核或暂停资格的报名队伍不会因为管理员移出指定战队列表而失去比赛概览；资格和报名状态继续在「报名战队」中管理。被拒绝且不再受邀的队伍无法查看私密比赛。关闭「启用比赛」后，管理员之外均不可见。


## 配置提示与提交限制

1. 在题目编辑的提示区填写内容。修改或拖动已有提示保留原 ID，避免已购买的队伍重复付费。
2. 在比赛编辑「提示规则」选择统一规则：免费、直接扣分或得分系数。下方按所选赛题显示提示，开启「单独调整」后覆盖该条提示；每页 10 题。
3. 在「提交限制」分别开启 Flag 提交次数、防御申请次数的上限。默认不限，下面按题开启「单独设置」。该题限制按整场比赛累计、全队共享，多小题也共用同一额度。
4. 保存比赛。选手在付费提示展开前看到确认框，提交区显示剩余次数，额度耗尽后不可继续提交。

防守题的作答区使用「攻击 / 防守」两个标签：攻击提交 Flag，防守上传 tar/tar.gz 补丁。系统构建后依次检测正常服务与漏洞利用。出题人检查器须区分退出码：0 通过；functional 的 1 表示服务异常；defense 的 1 表示漏洞仍可利用；其他非零值表示检查器自身异常。不要把网络故障、脚本异常直接当作攻击成功。完整协议见 [比赛规则](COMPETITION-RULES.md)，示例见 [攻防题示例](../examples/attack-defense/README.md)。

失败结果与重新提交入口在同一区域，补丁受理后消耗一次申请；冷却仍为 1 分钟。AWDP 成功完成防守小题，AWD 成功替换本队运行环境。已完成的一次性防守隐藏重复提交，逐轮重新提交及 AWD 修复保持可用。
