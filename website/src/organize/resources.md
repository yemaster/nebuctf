# 资源与次数限制

资源限制分为累计开启次数和同时使用上限。前者决定能重开多少次，后者决定同一时间占用多少环境，两者独立生效。

## 统一开启次数

在「编辑比赛 → 资源限制」填写「每队每题最多开启」。默认留空，不附加次数限制；填 0 禁止开启。

这里按每支战队、每道题分别累计。例如统一设置为 3 次，战队在 A 题开启两次后，A 题还剩一次，B 题仍有三次。

## 单题覆盖

展开「赛题设置」中的题目，在「靶机开启次数」选择：

| 方式 | 结果 |
| --- | --- |
| 跟随比赛 | 使用比赛的统一上限 |
| 不限制 | 取消本题的累计次数限制 |
| 单独设置 | 为本题填写独立上限，0 次表示禁止开启 |

单题的「不限制」不会取消平台并发、CPU、内存和冷却限制。

## 如何计次

成功启动一次计一次。排队和创建期间暂占次数，创建失败并完成清理后返还；已成功启动的环境停止、到期或后来发生故障，都不退回该次记录。重开会再次计次，续期不计次。

多容器整组视为一次开启。AWD 自动分配与重启遵守相同规则。练习、赛后练习、管理员测试、公共靶机和判题临时容器不使用这个比赛额度。

选手会在靶机区域看到剩余次数。额度用完不停止现有环境，只阻止下一次开启。调整上限后按本场已有成功记录计算，不会从零重计。

## 同时使用上限

在同页分别填写靶机和动态附件的每队、全场上限。留空不附加比赛限制，0 禁止新建。排队、启动、运行、待回收环境都占用名额；资源清理完成后才释放。

平台资源池还会检查容器总数、CPU 和内存。多容器的资源开销按各服务合计，但比赛的每队环境数量按整组计一个。为比赛安排容量时，应把辅助服务和判题环境的开销算进去。
