# 时间与计分

比赛外层时间决定赛事何时开始和结束，作答阶段进一步约束客观题和实操题。管理员应在比赛说明中写明实际采用的时间和计分规则。

## 作答时间

客观题和实操题可以分别设置固定时段，或允许战队在开放窗口内自由开始。自由开始由本队首次开始操作建立计时，队员共用同一份计时，不是各自拥有完整时长。

实际作答截止受比赛结束时间和阶段窗口约束。客观题最终提交后，全队不能继续修改；实操题的提交、环境和防御申请按对应阶段检查。

## 固定分与动态分

题库保存默认积分，在比赛赛题设置中可选择沿用题库、固定分或动态分。覆盖本场分值不会修改题库默认值。

动态分值按当前解题人数计算，使用抛物线衰减：

```text
分值 = max(最低分, ceil(初始分 + (最低分 - 初始分) × (解出数 / 衰减参数)²))
```

题目当前分值应用到已解出的战队。多小题分别按自己的解出数计算，不因另一小题被解出而衰减。同分时按平台的解题时间规则排序。

## 轮次计分

AWDP 和 AWD 可以使用轮次规则。统一轮次时长用于划分结算区间，单题设置决定哪些攻击、防御或服务状态参与该轮计算。应先确定计分目标，再配置轮次分值和 Flag 有效期。

AWDP 的攻击与防御分别判定；AWD 还需要服务巡检和轮换 Flag。详细流程见 [AWDP 与 AWD](../authoring/attack-defense)，不要仅凭题型名称推断比赛分值。

## 提示与提交次数

提示可以免费，也可以设置扣分。扣分确认后保存当次规则，之后调价不会追扣或退还已经购买的提示。

Flag 和防御申请可分别设置每队每题的累计次数。正确、错误、重复的 Flag 提交都计次；防御补丁受理后计次，即使校验失败也会消耗。无效请求、权限检查失败和未受理的请求不计次。

## 解锁与互斥

前置依赖可要求本队或全场任一队完成前置题目；完成条件可选全部或任一。多小题需要全部完成才算整题通过。

互斥组用于让战队选择一条路线。首次正式提交受理后，同组其他题目会隐藏并禁止直接访问，错误 Flag 也会选定路线。作答前应向选手说明该规则。

## 封榜

封榜后，公开排行榜和题目解题信息按封榜时刻显示；比赛结束后恢复完整结果。选手仍可在允许的作答时段提交。封榜不是提前结束比赛，也不会清除后续提交。
