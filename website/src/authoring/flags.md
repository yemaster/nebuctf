# Flag 与多个小题

静态 Flag 由出题人设置；动态 Flag 由平台按题目、比赛及个人或战队生成。同队成员使用同一个比赛答案，练习、比赛和测试互相隔离。

## 静态 Flag

在管理界面填写答案。Flag 区分大小写且保留空格，保存后只用于校验，不会返回明文。再次编辑时留空保留原值。

公共容器使用的静态 Flag 需要由镜像自行提供，且与管理界面的答案一致。平台不能从校验摘要恢复并注入明文。

## 动态模板

在「Flag 与计分」选择动态 Flag，填写模板并预览。新题默认模板为 `flag{[GUID]}`。

| 模板 | 用途 |
| --- | --- |
| `NebuCTF{[GUID]}` | 自定义前缀与 UUID |
| `NebuCTF{web_[TEAM_HASH]}` | 加入战队专属标识 |
| `[LEET]NebuCTF{hello_world_[TEAM_HASH]}` | 结合字符替换和标识 |
| `[CLEET]NebuCTF{hello_world_[TEAM_HASH]}` | 字符替换允许特殊符号 |

模板及结果最多 256 字符，变化空间不足的短模板需要加入 `[GUID]` 或 `[TEAM_HASH]`。预览仅供检查格式，不是某支队伍的真实答案。

普通动态环境重建后答案保持稳定；AWD 按轮次更新。已有题目模板留空时保留旧派生方式。不要把含特殊字符的答案直接拼接到 Shell 或 SQL 中。

## 多个小题

选择多个小题后，为各小题填写名称、分值和可选模板。小题模板留空时沿用题目模板，但不同小题仍生成不同答案。全部小题解出后才算整题完成。

动态题在「Flag 注入」逐行设置环境变量名。默认是 `FLAG_1`、`FLAG_2` 等，保存后与小题 ID 绑定，重排不会交换答案。变量名只能使用大写字母、数字和下划线，不能重复或占用系统保留名称。

## 指定注入容器

添加辅助服务后，每个 Flag 下方会显示容器选择。选中需要接收答案的服务，至少保留一个，可同时选择多个。只希望后端接收 Flag 时，先选中后端，再取消主服务。

| 环境变量 | 当前容器收到的内容 |
| --- | --- |
| 配置的变量名 | 分配给该容器的小题答案 |
| `FLAG` | 分配给该容器的第一个答案，兼容旧镜像 |
| `FLAG_COUNT` | 多小题模式下，分配给该容器的答案数量 |
| `FLAGS_JSON` | 多小题模式下，小题 ID 到答案的映射 |

未选中的容器不会收到这些动态答案。动态附件生成器收到完整映射；AWD 使用指定容器中的 `/run/nebuctf/flag` 文件。修改配置不会重写正在运行的实例快照。
