# 创建与发布

在「管理中心 → 题目」新建题目，先选择题型，再填写内容、答案和资源。题目可以独立开放练习，也可以只在比赛中使用。

## 选择题型

| 题型 | 适合的内容 |
| --- | --- |
| 客观题 | 选择、判断和填空类答卷 |
| CTF | 提交 Flag，可配静态附件、专属附件或靶机 |
| AWDP | 攻击获取 Flag，并上传补丁完成防御校验 |
| AWD | 战队独立服务、轮换 Flag、攻击与可用性检查 |

同场比赛可以混合选题。资源类型与题型分开配置，普通 CTF 题也可以同时提供附件和环境。

## 填写题面与答案

题面使用 Markdown，写明解题目标、入口和必要约束。平台不渲染原始 HTML，上传附件后使用实际下载链接。

在「Flag 与计分」配置静态或动态 Flag、分值及小题。静态 Flag 编辑时留空表示保留原值，平台不会回显旧答案。需要多个独立步骤时，添加多个小题，分别设置名称和分值。

## 配置资源

容器题在「靶机配置」填写镜像、资源、端口和访问方式；需要数据库等辅助服务时，继续配置[多容器](./multi-container)。附件在「附件管理」上传，专属文件则设置[动态附件生成器](./attachments)。

先保存题目，再测试已保存的配置。环境变量、Flag 模板和注入容器都以保存后的内容为准。

## 测试和发布

测试靶机用于检查启动、入口、Flag 和服务逻辑，不计入比赛成绩。测试环境也占用平台配额并遵守操作冷却，完成后及时释放。

确认题目可正常完成后启用。允许个人练习时打开「开放练习」，未公开的比赛题不要打开。AWD 仅用于比赛。

有解题记录、正式活跃环境或待处理防守任务后，核心判题、资源及计分参数可能锁定。需要修改时创建新版本题目，保留已有记录的含义。
