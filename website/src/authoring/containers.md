# 容器题目

容器镜像需要适应平台的非特权运行方式。先在本地构建并验证镜像，再导入平台配置。

## 镜像要求

服务以 `65534:65534` 运行，根文件系统只读，capabilities 全部移除，并禁止提权。可写临时目录为 `/tmp`，不能依赖宿主目录、Docker Socket、设备或特权模式。

服务监听 `0.0.0.0`，端口与题目配置一致。需要写入的缓存和临时文件应放到允许目录；运行时安装依赖、修改系统目录或切换用户通常不适用。

建议镜像声明 `HEALTHCHECK`。平台等待服务就绪后才提供入口，未声明健康检查时只能检查进程是否运行。健康检查的超时应适应实际 CPU 配额。

## 配置主服务

在「靶机配置」启用环境，选择镜像，设置 CPU、内存、服务端口和访问方式。默认镜像前缀为 `nebuctf/`，实际允许范围由部署者配置。

| 分配方式 | 使用方式 |
| --- | --- |
| 独立靶机 | 每个练习用户或参赛战队一组环境，可注入动态 Flag |
| 公共靶机 | 同一题目和赛场共享，由管理员启动，静态答案由镜像提供 |

启动命令每行是一个参数，不会自动经过 Shell 解释。需要执行脚本时，在镜像内准备脚本并明确指定入口。

## 访问方式

端口直连为主服务分配宿主端口，适用于 HTTP 和 nc。泛域名模式通过网关转发 HTTP/WebSocket，题目内仍提供明文 HTTP；TLS 由外部代理处理。

选择泛域名不会自动创建 DNS 和证书，先让部署者完成[网络配置](../deploy/network)。nc 题使用端口入口，选手可在网页终端连接。

## 启动与回收

镜像须提前就绪，题目启动不会自动拉取任意远程镜像。先在 [Docker 镜像管理](./images)拉取或上传，再保存并测试。

CPU、内存、PID、时长和数量限制始终生效。启动失败先看错误、镜像健康检查和目录权限；修改后重新保存测试。停止或到期后环境被回收，容器内修改不作为持久资料保留。
