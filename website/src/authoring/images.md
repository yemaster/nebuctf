# Docker 镜像管理

「管理中心 → Docker 镜像」显示 Runtime 所在主机的镜像。题目编辑的靶机配置和防守校验页面也提供跳转入口。

## 查看使用关系

镜像按是否被题目使用分类，同一题目的相关镜像在对应标题下展示。修改题目配置后，检查主服务、辅助服务和检查器是否都已就绪。

镜像存在于平台 API 或 k3s 的镜像存储，不代表 Docker Runtime 能使用它。题目镜像必须在实际执行靶机的 Docker 主机中就绪。

## 拉取指定镜像

点击拉取，填写完整镜像引用并确认。引用必须满足平台的仓库前缀策略。生产比赛建议固定 tag，条件允许时使用 digest，避免同一名称的内容发生变化。

进度弹窗显示任务状态、下载层和滚动日志。关闭弹窗不会取消已经受理的任务，可重新打开查看结果。失败时先检查镜像名称、网络和仓库访问条件。

## 上传镜像

在可构建镜像的机器上导出 Docker save 归档：

```sh
docker save nebuctf/challenge:1 -o challenge.tar
# 也可以压缩后上传
gzip challenge.tar
```

在镜像页选择上传，支持 tar 和 tar.gz，最大 2 GiB。上传完成后还需要等待 Runtime 校验并导入，不能把上传完成视为镜像已经就绪。

归档中的全部标签都要满足允许的前缀。`docker export` 导出的是容器文件系统，不能替代 `docker save` 镜像归档。

## 测试题目

镜像就绪后返回题目，保存配置，再启动测试靶机。拉取成功仅说明镜像可用，服务能否在非 root、只读根和指定配额下工作仍需要实际验证。
