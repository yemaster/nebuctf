# 多容器与网络

一个题目环境可包含 1 个主服务、最多 7 个辅助服务和 4 个网络。平台以整组为单位启动、续期和回收。

## 添加服务

在「靶机配置 → 高级容器配置」设置主服务、辅助服务和网络。每个辅助服务分别填写名称、镜像、CPU、内存、命令和环境变量。

主服务的固定名称是 `main`。辅助服务使用小写字母开头的名称，可包含数字和连字符。同一网络中通过服务名访问，例如 `backend:8080`。

辅助服务可依赖其他辅助服务。依赖不能循环，也不能指向 main；依赖服务就绪后启动后续服务，全部辅助服务就绪后再启动主服务。

## 安排网络

平台保留 `default` 网络，主服务必须连接它。可另外创建内部网络，将数据库等服务放入内部网络，主服务同时连接需要访问的网络。

例如，主服务连接 `default` 和 `data`，数据库只连接内部 `data` 网络。主服务负责对外入口，数据库不发布宿主端口。端口直连时，default 网络不能开启内部隔离。

内部网络用于限制连接范围，不替代服务鉴权。关闭内部隔离也不会绕过宿主上的平台防火墙。不要将题目服务连接到平台管理网络。

## 分配 Flag

回到「Flag 注入」，逐个选择答案对应的容器。以下配置表示只有 backend 接收单个动态 Flag：

```json
{
  "flag_mode": "dynamic",
  "flag_targets": ["backend"]
}
```

这是题目配置片段，需要与实际的 backend 服务定义一起保存。多小题则分别配置自己的 `flag_targets`。详见 [Flag 与多个小题](./flags)。

## 配额与失败处理

全局 CPU、内存和容器数按所有服务合计；比赛的环境数量与开启次数按整组计一次。某个辅助服务启动失败会导致整组启动失败，运行期间辅助服务退出也会使环境停止。

对外入口、终端和补丁更新仍以主服务为目标。AWDP/AWD 的校验环境会使用同样的辅助服务和网络配置，补丁只更新 main。辅助服务不可发布额外宿主端口或添加宿主挂载。
