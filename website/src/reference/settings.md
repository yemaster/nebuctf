# 系统设置与权限

平台级设置影响所有比赛。比赛级限制则只作用于对应比赛，不能突破平台资源池和账户权限。

## 站点与邮件

在管理中心设置站点名称、页脚和公开信息。启用邮箱验证前配置 SMTP，并使用实际邮箱测试发送、回执和链接可达性。邮箱白名单会限制注册范围，应与办赛对象一致。

系统消息可按用户、战队或比赛范围发送。比赛审核、WriteUp 反馈和时间提醒进入消息中心；需要全体选手持续查看的规则仍应写在比赛说明或公告中。

## 角色与授权

平台支持管理员、普通用户、自定义角色，以及单题目或单比赛授权。为协作出题人和赛事工作人员分配完成任务所需的范围，并使用普通账号检查实际入口。

API KEY 不会提升持有者原有权限。拥有某个密钥身份，也不表示该用户自动成为管理员。

## 容器策略

容器策略管理默认时长、续期、环境数量和替换行为。CPU、内存与全局数量还受到部署配置约束。数量已满时，可按策略要求用户释放或确认替换现有环境。

自动替换不能绕过比赛的累计开启次数；次数耗尽仍会阻止新开。清理未完成的资源继续占名额。

## 流量与采集

流量功能包含统计与 PCAP 采集，需先准备对应镜像、目录和配额。按赛事实际需要启用，限制保留量，并明确采集用途和访问人员。

采集文件可能包含选手请求和解题数据，只应通过授权入口读取。平台文件备份与数据库备份应分别覆盖需要长期保留的采集内容。

## AI 转发

部署者可以配置 OpenAI 或 Anthropic 兼容路由。它使用独立的上游配置和凭据，不与个人 API KEY 共用权限。启用前检查额度、允许模型和调用范围，不要把上游密钥写入题面或公开文档。
